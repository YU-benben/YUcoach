# 人物锁定 v1（App 1.1.1+3）

文档复核：2026-10-16，适用 App 1.1.1+3。

本版在上传后的分析流程中加入「锁定本次运动员」。继续限定固定侧面、原始恒定高帧率视频（至少 120 fps），新 App 和电脑服务端需一起更新。安装包为项目根目录的 `YUcoach-target-lock.apk`。

## 操作

1. 在电脑重启分析服务，手机安装新版，确认服务地址可连接。
2. 上传原片，填写侧面、没有镜头跟随。
3. 在选人页通过滑条和 ±1 / ±10 帧找到目标清晰、与其他人分离的一帧。
4. 在画面拖动矩形，框住目标运动员完整身体。该帧即起始帧。框内不要包含其他人。
5. 移到合适的结束帧，点击「将当前帧设为结束帧」。尽量选择短而连续、人物完整可见的区间，避开出画、遮挡与交叉。
6. 可点击「返回选人帧核对」查看绿色框。确认后提交。移动到其他帧时不显示旧框，避免把静止框误认为跟踪结果；重新框选会重置起止区间。

取消选人不提交分析、不扣额度。参数非法也在服务端扣额度之前拦截。

在 PowerShell 中启动更新后的服务（先在原服务窗口按 Ctrl+C 停止旧服务）：

```powershell
Set-Location D:\YUcoach
.\.venv\Scripts\python.exe -m backend.server.app --port 8770
```

## 两种模式的含义

默认的人工确认计时：选人框及区间确定本次标注对象；接触事件只能标在选定区间内。标注页可回到选人帧查看绿色框核对身份。它仍由人确认每个事件属于同一运动员，**不运行姿态模型或自动身份跟踪**，原有四项时间指标的口径不变。

实验性自动分析：在选定区间运行姿态模型，并逐帧关联目标。YOLO 和 RTMPose 都接入同一个关联器；不会在每帧重新按「最大的人」或「置信度最高的人」选人。未提供选人参数的旧 API 调用仍保留旧行为，这不是建议使用的入口。

## 自动关联方法

- 起始帧：以用户框与模型候选框的重叠程度确定唯一候选。没有足够匹配、多个候选接近或人物重叠时停止。
- 后续帧：用上一个目标的位置、平滑位移预测、人体高度变化及上半身 HSV 颜色直方图关联。初始外观参照保持固定，不持续更新成路人。
- YOLO 使用检测框，并排除躯干关键点不足的候选。RTMPose 没有返回人体框，使用置信度合格的可见人体关键点生成框，缺少肩髋核心点时拒绝作为候选。
- 空检测、不连续帧、突然跳转、外观偏差、明显人物框重叠或两个匹配分数接近时，立即中断。已经中断的关联器不重新找人，不插值跨过身份缺口，也不生成该次报告。
- 错误提示会给出原视频帧号，便于缩短区间或换素材后重新框选。首版不支持中断后续接、多目标同时分析或跨遮挡重新识别。

这是位置与外观的保守关联方法，不是人脸识别，也没有采用经过短跑数据验证的 ReID 网络。相似衣服、严重模糊、漏检其他人物、检测框漂移仍可能误关联；不能承诺绝不换人。蹲踞到站立等姿态大幅变化也可能导致提前停止。停止条件较严格，可能牺牲可用时长，应以复核为准。

人物锁定不等于空间指标已验证。旧自动分析的空间标定、角度和接触算法仍属于实验性流程；本次没有将这些指标升级为可信测量。推荐继续用默认人工接触帧计时流程。

## 存档与排查

成功任务仍归档到 `D:\YUcoach\data\manual_timing\<job_id>\`，目录名延续上一版，可能包含人工计时或实验性自动分析：

- 原视频、`review.json`、`report.json`。
- `review.json` 新增 `target_selection`：协议、起始帧、结束帧、归一化选人框和确认状态。
- 自动分析额外包含 `target_tracking.json`：选人参数、关联方法、原始帧号及逐帧目标框。

自动跟踪中断时不生成报告，诊断轨迹写在 `.cache\keyframes\<job_id>\target_tracking.json`，状态为 `lost` 或 `incomplete`。失败任务不进入成功数据集；原上传仍遵循现有临时上传清理策略。运行中失败沿用现有额度机制，**本版没有新增失败退款机制**。

算法版本为 0.4.0，自动分析的模型配置会附带 `target_lock=position_velocity_hsv_v1`。报告备注说明人工选人区间及人工核对/自动关联来源，不将框选称为身份认证。

## 验证与边界

新增测试覆盖：候选顺序变化、旁人更大、目标消失、不同颜色人物占据原位置、人物交叉、突然跳转、时间断帧、起始框重叠、参数越界、两个模型的选择接入、限定分析区间、丢失后禁止生成报告、失败帧轨迹存储，以及 Flutter 原图坐标框选和区间提交。

使用现有 YOLO 权重检查项目真实多人样例：手动框定前景蹲踞运动员后，0–10 帧完成关联，框位于目标身上；延长到 0–30 帧时在第 15 帧拒绝继续匹配，保留中断记录。这个样例说明可以运行并保守停止，不证明高速跑动或完整起跑过程的身份精度。对应画面和轨迹位于 `output/target_lock_verification/`。

尚未进行包含多人高速交叉、同服装和遮挡的标注测试集评估，也没有量化 ID 切换率。因此本版应视为可复核的首版功能，而非经过精度认证的跟踪系统。
