# 参考值严格匹配（规则版本0.3.0）

文档复核：2026-10-16，适用 App 1.1.1+3。

## 行为变化

过去：按指标、视角、阶段查找；可退回其他训练水平或全程均值。

现在：指标、视角、阶段、性别、训练水平、专项、测量窗口、步次、跑动负荷条件必须一致。来源限制了年龄时还需年龄匹配。未知信息不作为通配符；多个同口径来源不自动选文件中的第一条。未匹配时保留测量结果，不输出偏差判断。

全程均值不能替代某个阶段，单次事件不能替代事件均值。膝角已经按实际着地事件所属阶段分组，不再把整段视频的均值冒充途中跑均值。规则自身声明的阶段仅用于筛选，不用于推断测量阶段。

## 参考文件字段

在现有YAML字段之外，支持：

```yaml
running_condition: unloaded  # unloaded / resisted / assisted / unspecified
step_number: 1              # 可选；从真实起跑开始的支撑编号，不是片段内第1个事件
load_protocol: vdec_20pct    # 仅阻力/助力需要；明确具体方案，同方案才可比较
```

指定step_number时，window必须为single_event；普通均值不能匹配某一特定步次。负荷方案标识需要包括影响可比性的条件，例如速度降幅、器械、坡度等，不能只命名为“重负荷”。无负荷条目不填load_protocol。

旧条目未声明running_condition时按unspecified保存，仍可加载和审计，但不能参与自动判定。不要为恢复原有结论而批量补填unloaded，应逐条核对原文。均值/标准差不转换为合格上下限。

年龄范围目前只匹配形如22-29或22–29的数值闭区间；未知/无法解析的限制不放行。mixed样本不自动替代男、女单组参考。

## 服务接口及命令行

POST /api/analyze新增可选字段：

```json
{
  "gender": "male",
  "level": "elite",
  "event": "100m",
  "athlete_age": 25,
  "running_condition": "unloaded",
  "complete_run": false
}
```

这些字段与原有video_id、username等一起提交。阻力/助力跑还须提供load_protocol。接口在扣分析额度前校验新增参数。没有提供人群字段时，报告原有默认资料不作为确认过的人群信息参与匹配。

complete_run必须是JSON布尔值；只有确认视频涵盖完整专项距离时才能设true。普通加速或途中跑短片不能勾选。分析使用max_frames截断时，全程确认自动失效。即使确认完整全程，也仍需验证现有步频算法与文献测量方法的可比性。

命令行支持--athlete-age、--running-condition、--load-protocol、--complete-run。用于匹配的人群还需明确给出--gender、--event、--level。直接调用run_pipeline或ReportInputs时，还应设置population_confirmed=True，表示这些人群信息已经明确提供。

## 本次没有完成的内容

- 没有修改文献数值或导入调研的11项候选记录。
- 没有给手机上传页增加年龄、负荷和全程确认控件；旧App仍能分析，但未知条件会阻止偏差判断。
- 没有实现从真实起跑开始自动编号的逐步指标。step_number匹配接口已准备好，不能把任意片段的第一次着地认定为起跑首步。
- 没有新增训练处方，也没有证明现有练习配对有效。

因此当前结论可能减少。报告会提示测量窗口/参考条件未确认，并且不再把“未触发规则”概括为“各项均正常”。要启用新文献，下一步需审核来源条件、完成App采集字段及逐步指标，再录入候选值。
