### 1.1 结构设计理由

| 决策 | 理由 |
|---|---|
| `domain/enums.py` 单一来源 | 枚举在多处使用，分散定义必然漂移 |
| `metrics/` 按视角分文件 | 与 `03-指标定义.md` 的分类一致，便于逐条对照实现 |
| `camera_motion/` 独立目录 | 是本项目的核心难点，需要单独测试 |
| `valid_window/` 独立目录 | 影响所有指标，必须可独立验证 |
| `contracts/` 独立目录 | 契约是跨语言资产，不属于后端 |
| `mobile/lib/models/` 自动生成 | **手写客户端模型必然与契约脱节** |
| `data/` 与代码分离 | 规则与标准值由教练反馈驱动调整，不应触发代码发版 |

## 3. 测试要求

### 3.1 各层要求

| 层 | 要求 | 重点 |
|---|---|---|
| 指标计算 | **必须手工验算** | 边界：全缺失点、单帧、除零、负值 |
| 角度计算 | **必须通过四象限用例** | `atan2` 的四个象限符号 |
| 帧率校验 | 必须覆盖三种方法 | 方法冲突、只有一种可用、全部失败 |
| 镜头运动检测 | 必须覆盖固定/轻度/明显三档 | 无背景特征的极端情况 |
| 视角校验 | 必须覆盖三视角 × 声明/推断四种组合 | 不一致时的处理 |
| 参考尺度 | 必须覆盖分道线法 / 肢体尺度 / 两者皆无 | 逐帧降级 |
| 有效测量窗 | 必须覆盖三档 | 边界值 |
| 契约序列化 | 必须有快照测试 | 字段改名会被快照捕获 |
| 规则引擎 | 每条规则一正一反一视角不匹配一阶段不匹配 | 阈值边界、滞回 |
| 端到端 | 至少 5 条样例视频 | 见 §3.4 |

### 3.2 手工验算的要求 ⚠️

> **指标计算的测试必须是手工验算，而不是"与上次输出一致"。**
>
> 后者只能防回归，不能防一开始就错。一个从第一天就错了十倍的计算，快照测试会忠实地一直通过。

**构造方法**：

```python
def test_shank_angle_touchdown_vertical():
    """小腿完全垂直：膝在踝正上方，期望 0°"""
    kp = make_keypoints(knee=(100, 100), ankle=(100, 300))
    assert shank_angle_touchdown(kp) == pytest.approx(0.0)

def test_shank_angle_touchdown_knee_forward_45():
    """膝在踝前方 45°"""
    kp = make_keypoints(knee=(300, 100), ankle=(100, 300))
    assert shank_angle_touchdown(kp) == pytest.approx(45.0)

def test_shank_angle_touchdown_knee_behind():
    """膝在踝后方，应为负值 —— 这条测的是 atan2 的符号正确性"""
    kp = make_keypoints(knee=(-100, 100), ankle=(100, 300))
    assert shank_angle_touchdown(kp) == pytest.approx(-45.0)
```

**每个指标至少 3 个手工验算用例**，且必须包含一个**符号正确性**用例。

### 3.3 必须存在的守门测试

**这八条测试对应八条设计原则，不得删除、不得跳过。**

| 测试 | 守住的原则 | 缺失的后果 |
|---|---|---|
| 角度四象限 | 符号正确性 | 前后方向颠倒，数值仍在合理范围 |
| **视角不匹配时指标不计算** | 视角绑定 | 矢状面/额状面混淆，结论完全错误 |
| 阶段不匹配时规则不触发 | 阶段绑定 | 系统性误报重新出现且不被发现 |
| `fps_declared ≠ fps_verified` 时用后者 | 不信任容器元数据 | 帧率问题回归 |
| `pixels_per_meter == null` 时位移指标返回 `insufficient_data` | 宁可不说不可说错 | 用像素当米输出 |
| **绝对速度类指标不存在** | 诚实的能力边界 | 有人后来"顺手"加上了速度 |
| `reliable: false` 的指标仍出现在响应中 | 不确定性可见 | 指标被静默隐藏 |
| **`insufficient_data` 必须带 `reason`** | 数据不足是明确状态 | 沉默被误读为"没问题" |

### 3.4 样例数据要求

`samples/` 中必须包含下列固定样例：

| 样例 | 特征 | 用途 |
|---|---|---|
| `side_240fps` | 侧面，240fps，有分道线，无遮挡 | 正常路径 |
| `side_tracking` | 侧面，镜头明显跟随，有效帧占比 60% | 验证跟踪处理 |
| `front_120fps` | 正面，120fps | 验证额状面指标 |
| `low_fps_60` | 60fps | 验证时间类指标降级 |
| `no_reference_scale` | 无分道线、无身高 | 验证位移类返回不足 |
| `fps_mismatch` | 声明 30，实际 60 | 验证帧率校验 |
| `view_mismatch` | 侧面视频请求额状面指标 | 验证视角绑定 |

## 4. 代码风格

### 4.1 Python

| 项 | 约定 |
|---|---|
| 格式化 | `ruff format`（行宽 100） |
| 检查 | `ruff check` |
| 类型标注 | **全部公开函数必须有** |
| 类型检查 | `mypy` 严格模式（`analysis/` 与 `domain/`） |
| 命名 | 变量/函数 `snake_case`；类 `PascalCase`；常量 `UPPER_SNAKE` |
| 文档字符串 | 公开函数必须有；**指标函数必须注明 `metric_id`** |

### 4.2 指标模块的强制注释格式

```python
def shank_angle_touchdown(kp: Keypoints) -> MetricResult:
    """
    metric_id : shank_angle_touchdown
    name_zh   : 着地胫骨角
    unit      : deg
    view      : side
    phase     : all
    requires  : knee, ankle
    min_fps   : 60
    needs_reference_scale : False

    formula   : segment_angle_from_axis(knee, ankle) @ touchdown
    spec      : docs/03-指标定义.md §3.2

    注意：必须使用 atan2，不得使用 arccos（会丢失前后方向）。
    注意：视角必须为 side，否则返回 view_mismatch。
    """
```

**要求**：指标函数必须注明 `metric_id` 与规范文档章节号。

> 理由：半年后你打开这个函数，需要能在 10 秒内找到它的规范定义，而不是重新推导一遍。

### 4.3 枚举的单一来源

```python
# backend/domain/enums.py
class View(str, Enum):
    SIDE = "side"
    FRONT = "front"
    BACK = "back"

class Phase(str, Enum):
    SET = "set"
    START = "start"
    ACCELERATION = "acceleration"
    TRANSITION = "transition"
    MAX_VELOCITY = "max_velocity"
    DECELERATION = "deceleration"
```

**任何地方需要使用枚举时必须从这里导入。** 不得在模块内重新定义字符串常量。

理由：`"max_velocity"` / `"maxVelocity"` / `"MAX_VELOCITY"` 的拼写差异不会报错，只会静默失配。

### 4.4 契约模型自动生成

```
contracts/*.schema.json  →  gen_models.py  →  mobile/lib/models/*.dart
                                          →  backend/api/schemas/*.py
```

**不得手写客户端模型。**

理由：手写模型与契约的漂移是必然的。契约改了字段名，前端不会报错，只会静默收到 `null`。

## 7. 错误处理

### 7.1 三类错误

| 类型 | 处理 | 示例 |
|---|---|---|
| 用户错误 | 返回 4xxx + `suggestion` | 素材帧率不合格、视角无法确认 |
| 系统错误 | 返回 5xxx + 记录日志 + 重试 | 模型推理 OOM |
| **数据缺陷** | **不报错**，返回 `insufficient_data` | 关键点缺失、无参考尺度 |

### 7.2 数据缺陷不得抛异常 ⚠️

> **缺关键点、帧率不足、无参考尺度、视角不匹配——这些不是错误，是业务状态。**

它们必须作为**正常响应**返回，携带 `insufficient` 说明，而不是抛异常或返回 4xxx。

| 错误做法 | 后果 |
|---|---|
| 抛 `KeypointMissingError` | 整个分析失败，教练看不到任何指标 |
| 返回 4001 | 教练以为视频不能用，实际只是某项指标不可测 |

**正确做法**：逐指标判断，能算的算，不能算的返回 `insufficient_data`。**部分可用优于全部失败。**

### 7.3 必须记录的关键决策

| 内容 | 用途 |
|---|---|
| 帧率校验：三种方法的结果与最终采信值 | 回答"时间指标为什么这样" |
| 镜头运动检测结果 | 回答"为什么某些指标没输出" |
| 视角校验结果 | 回答"为什么某些指标没输出" |
| 参考尺度来源与数值 | 回答"位移指标怎么算的" |
| 有效测量窗的逐帧标记 | 回答"用了哪些帧" |
| 每个 `insufficient_data` 的判定原因 | 回答"为什么这项没测" |

**缺了这些，事后无法复现问题。**

| 项 | 要求 |
|---|---|
| 多租户隔离 | 所有查询**必须**带 `team_id` 过滤 |

| 本周完成 | 对应哪个阶段的哪一项 |
| 阻塞项 | 具体卡在哪里 |
| 假设状态变化 | 有无新验证结果 |
| 下周计划 | 最多 3 项 |

### 11.2 警示信号

| 信号 | 含义 | 处理 |
|---|---|---|
| 任一阶段超期 > 50% | 进度风险 | 重评范围，砍功能 |
| 质量门被反复绕过 | 工程纪律失效 | 立即停止新功能，修复工程基础 |
| 连续 2 周无假设验证 | 闭门造车 | 优先做验证 |
| 教练复核误报率 > 20% | 规则库不可用 | 暂停新增规则，先修现有 |
| 某类 `insufficient_data` 占比 > 40% | 拍摄引导失效 | 优先改进 App 的拍摄指导 |
