## 1. 术语表（唯一语言）

> 以下术语在文档、代码、界面、口头沟通中含义必须完全一致。**不得使用同义词。**

| 术语 | 定义 | 禁止混用 |
|---|---|---|
| 采集场次 Session | 一次上传产生的全部数据（一个视频 + 元数据 + 分析结果） | 不要叫"任务""记录" |
| 视角 View | 拍摄方位：侧面 / 正面 / 背面 | 不要叫"机位""角度" |
| 姿态数据 Pose | 逐帧的人体关键点坐标 | 不要叫"骨骼""关键帧" |
| 指标 Metric | 由姿态数据计算出的单一数值 | 不要叫"参数""数据" |
| 结论 Finding | 由规则判定的技术问题描述 | 不要叫"建议""结果" |
| 处方 Drill | 针对某个技术问题的训练手段 | 不要叫"动作""练习" |
| 阶段 Phase | 短跑的一个时间段 | 不要叫"时期" |
| 事件 Event | 一个瞬时时刻（着地、离地等） | 不要叫"标签" |
| 关键帧 Keyframe | 发生事件的帧 | 不要叫"重点帧" |
| 镜头跟踪 Camera Tracking | 拍摄过程中镜头跟随运动员移动 | 不要叫"跟拍"（有歧义） |
| 有效测量窗 Valid Window | 运动员处于画面中心区域、测量可信的帧范围 | 不要叫"有效帧"（易混） |
| 透视误差 Perspective Error | 视线偏斜导致的角度投影误差 | 不要叫"畸变"（畸变是镜头问题） |
| 畸变校正 Undistort | 修正镜头几何畸变 | **不要叫"标定"** |
| 参考尺度 Reference Scale | 画面中已知长度的物体，用于像素↔米换算 | 不要叫"标定" |
| 实测帧率 fps_verified | 经校验认定的真实帧率 | **不要叫"帧率"**（有歧义） |
| 质量码 q | 单个关键点的可信度（0/1/2） | 不要叫"置信度" |
| 置信度 confidence | 计算结果的数值可信程度（0–1） | 不要叫"质量" |
| 可靠性 reliable | 该指标在方法学上是否可用于结论 | 不要叫"准确度" |
| 数据不足 insufficient_data | 明确判定为无法评估的状态 | **不要叫"正常"或留空** |

### 1.1 三个最容易混淆的概念

| 概念 A | 概念 B | 区别 |
|---|---|---|
| **畸变校正** | **参考尺度** | 前者修正镜头的几何失真（画面弯曲），后者提供像素到米的换算。是两件完全不同的事，都需要做 |
| **透视误差** | **畸变** | 前者因为运动员偏离画面中心产生，后者因为镜头光学特性产生。前者无法通过标定消除 |
| **置信度** | **可靠性** | 前者回答"这个数准不准"，后者回答"这个数该不该用"。见 §5 |

## 2. 四层数据模型

```
Session（采集场次）
  └─ Pose（姿态数据）          客观：点在哪
       └─ Metric（指标）        客观：数值多少
            └─ Finding（结论）  判断：说明什么
                 └─ Drill（处方）建议：练什么
```

### 2.1 层间规则（不可违反）

| # | 规则 | 违反后果 |
|---|---|---|
| 1 | 数据只能向下派生，不能向上引用 | Metric **不得**引用 Finding |
| 2 | 每层必须能独立存在 | 没有 Finding 时，Metric 依然有意义（用于趋势） |
| 3 | 每层的版本独立 | 改规则不需要重算指标 |
| 4 | 每层必须能独立获取 | 接口可分别拉取 |

### 2.2 事实与判断的分界

| 层 | 性质 | 能否自动生成 | 出错的责任归属 |
|---|---|---|---|
| Pose | 事实 | 是 | 有 `q` / `confidence` 兜底 |
| Metric | 事实 | 是 | 有 `reliable` / `reliability` 兜底 |
| Finding | **判断** | 否 | **必须能追溯到 `rule_id`** |
| Drill | 知识 | 否 | 由教练反馈迭代 |

> **这是全套设计中最重要的一条分界。**
>
> Pose 和 Metric 是"算出来的"，Finding 和 Drill 是"判出来的"。前者错了可以重算，后者错了会失去教练的信任，且无法自动发现。

## 3. 实体关系

```
Team（队伍）
  ├─ Athlete（运动员）
  │    └─ Session（采集场次）  ← 一次上传 = 一个 Session
  │         ├─ Pose（姿态数据）
  │         └─ Analysis（分析记录）  ← 同一 Session 可多次分析
  │              ├─ Metric[]（指标）
  │              └─ Finding[]（结论）
  │                   └─ Drill[]（处方）
  └─ User（用户）  ← 一人可属多队
```

**关键设计**：`Analysis` 与 `Session` 是一对多。同一段视频，换模型或改算法后重新分析会产生新的 Analysis 记录，**旧记录保留不删除**。这样才能回答"为什么这次和上次不一样"。

### 4.1 为什么是 16 点而不是 COCO 17 点

| 决策 | 理由 |
|---|---|
| **不需要肘、腕** | 短跑分析不涉及上肢细节，标注它们只增加工作量与出错面 |
| **必须有 `toe` 和 `heel`** | 着地判定、离地判定、着地方式判定都依赖足部。COCO 17 点没有足部点 |
| **必须有 `pelvis_center` / `shoulder_center`** | 正面与背面视角的额状面指标需要骨盆与肩的相对关系。侧面视角用不到，可留空 |

### 4.2 左右定义 ⚠️

> **`_r` / `_l` 指运动员自身的右侧 / 左侧，不是画面左右。**

| 视角 | 判定方法 |
|---|---|
| 侧面 | 运动员面朝跑动方向，其右手侧为 `_r` |
| 正面 | 画面中的左侧是运动员的右侧 |
| 背面 | 画面中的左侧是运动员的左侧 |

**这是最常见的标注错误之一。** 标反了不会报错，但会让所有分侧统计完全颠倒。

### 4.3 视角与关键点的关系

| 关键点 | 侧面 | 正面 | 背面 |
|---|---|---|---|
| `head` `neck` | ✅ 必需 | ✅ 必需 | ✅ 必需 |
| `shoulder_*` | ✅ 必需 | ✅ 必需 | ✅ 必需 |
| `hip_*` | ✅ 必需 | ✅ 必需 | ✅ 必需 |
| `knee_*` `ankle_*` `toe_*` | ✅ 必需 | ✅ 必需 | ✅ 必需 |
| `heel_*` | ⭕ 选标 | ⭕ 选标 | ⭕ 选标 |
| `pelvis_center` | ⭕ 不用 | ✅ 必需 | ✅ 必需 |
| `shoulder_center` | ⭕ 不用 | ✅ 必需 | ✅ 必需 |

## 5. 数据质量状态枚举

### 5.1 质量码 `q`（标注层，单点）

| 值 | 含义 | 分析时处理 |
|---|---|---|
| `2` | 清晰可见，位置无歧义 | 作为有效值 |
| `1` | 可见但有遮挡/模糊，位置存疑 | 降权使用 |
| `0` | 不可见 / 出画 / 未标注 | **不参与计算，不插值** |

### 5.2 置信度 `confidence`（计算层，连续）

| 范围 | 含义 |
|---|---|
| 0.9 – 1.0 | 高：关键点清晰、无遮挡、处于画面中心 |
| 0.7 – 0.9 | 中：轻微遮挡或处于画面边缘 |
| 0.4 – 0.7 | 低：明显遮挡、插值补出、或明显偏斜 |
| 0.0 – 0.4 | 极低：不应单独支撑任何结论 |

**展示规则**：`confidence < 0.7` 时界面必须显式标注。

### 5.3 可靠性等级 `reliability`（方法学，离散）

| 等级 | 含义 | 使用限制 |
|---|---|---|
| `A` | 二维视频可精确测量 | 可直接用于结论 |
| `B` | 可测量但受假设影响 | 可用于结论，需附不确定性说明 |
| `C` | 参考价值有限 | **仅用于趋势对比，不得单独支撑结论** |

### 5.4 可用性 `reliable`（布尔）

| 值 | 含义 |
|---|---|
| `true` | 该指标在当前数据条件下可用于判断 |
| `false` | 方法学上不可用于判断 |

**`confidence` 与 `reliable` 是两个不同问题，不可合并：**

> 跟踪拍摄时运动员处于画面边缘（`confidence` 0.6），但角度本身测得很清楚（数值稳定）。
> 这可能既"测得准"又"不该用"——因为偏斜导致的系统性偏差无法通过重复测量发现。

### 5.5 结论严重度 `severity`

| 值 | 含义 | 报告位置 | 上限 |
|---|---|---|---|
| `major` | 显著影响成绩，应优先纠正 | 报告主体 | 2 |
| `minor` | 有改进空间，非紧急 | 报告主体 | 1 |
| `info` | 观察性描述 | 折叠区 | 不限 |
| `insufficient_data` | 数据不足以判断 | **独立区块，附改进建议** | 不限 |

**报告主体条目总数 ≤ 3。**

### 5.6 数据不足原因 `reason`

| 值 | 含义 |
|---|---|
| `low_frame_rate` | 帧率不足 |
| `view_mismatch` | 该指标不适用当前视角 |
| `no_reference_scale` | 无参考尺度，位移类不可用 |
| `camera_motion` | 镜头运动导致该指标不可靠 |
| `occlusion` | 关键点被遮挡 |
| `missing_event` | 缺少所需事件 |
| `perspective_error` | 运动员偏离画面中心过远 |
| `frame_rate_unverified` | 帧率无法校验 |
| `insufficient_samples` | 完整步次少于 3 个 |

**`insufficient_data` 必须显式输出，不能沉默。** 沉默会被教练误读为"没问题"。

## 6. 视角枚举（3 个）

| ID | 中文 | 拍摄位置 | 可见平面 |
|---|---|---|---|
| `side` | 侧面 | 跑道侧面 | 矢状面 |
| `front` | 正面 | 运动员前方 | 额状面 |
| `back` | 背面 | 运动员后方 | 额状面 |

### 6.1 视角绑定的含义

> **视角不是元数据，是决定计算内容的参数。**

| 视角 | 可计算指标类别 |
|---|---|
| `side` | 矢状面角度、时间参数、步幅 |
| `front` / `back` | 额状面角度、对称性指标 |

**不得跨视角计算指标。** 用正面视频算"膝关节角"得到的是完全不同的几何量。

### 6.2 视角的传递

视角通过 `session.view` 字段传递，所有指标计算与规则判定必须检查它。当请求的指标与视角不匹配时，返回 `insufficient_data`，原因为 `view_mismatch`。

## 7. 阶段枚举（6 个）

| ID | 中文 | 界定 | 关键特征 |
|---|---|---|---|
| `set` | 预备姿势 | 起跑器就位至枪响 | 静态 |
| `start` | 起动 | 枪响至蹬离起跑器 | 蹬伸 |
| `acceleration` | 加速段 | 蹬离起跑器至第 4 次着地 | 躯干前倾最大 |
| `transition` | 过渡段 | 第 5 次着地至躯干角稳定 | 身体逐渐直立 |
| `max_velocity` | 途中跑 | 躯干稳定至速度峰值后衰减 5% | 速度最高 |
| `deceleration` | 减速段 | 之后至终点 | 速度下降 |

### 7.1 为什么阶段必须绑定

**同一个数字在不同阶段含义相反。**

| 指标 | 加速段 | 途中跑 |
|---|---|---|
| `trunk_lean`（躯干前倾角） | 45–60° 是**优秀** | 5–15° 才是正确；>20° 是**严重错误** |

因此：
- 所有标准值必须声明 `applicable_phase`
- 判定规则必须声明 `phase`
- 当 `ref.applicable_phase ≠ metric.phase` 时，**禁止计算偏离度**

**违反此条的典型后果**：用途中跑的标准区间（5–25°）去判加速段，会对所有正常运动员报出"躯干前倾过大"，形成系统性误报。

## 8. 事件枚举（8 个）

| ID | 中文 | 定义 | 允许不确定度 |
|---|---|---|---|
| `set_position` | 预备就位 | 运动员进入稳定预备姿势 | ±3 帧 |
| `gun_fire` | 发令 | 枪响 / 发令信号可见的那一帧 | ±1 帧 |
| `block_clearance` | 蹬离起跑器 | 后脚离开起跑器踏板的第一帧 | ±1 帧 |
| `touchdown` | 着地 | 鞋底与地面出现可见接触的第一帧 | ±1 帧 |
| `midstance` | 支撑中期 | 重心竖直位置接近最低、膝角接近支撑期最小值 | ±1 帧 |
| `toe_off` | 离地 | 趾尖与地面失去接触的最后一帧 | ±1 帧 |
| `swing_peak` | 摆动最高点 | 摆动腿大腿前摆至最高、膝折叠最充分 | ±1 帧 |
| `finish` | 终点 | 躯干到达终点线垂直面的帧 | ±1 帧 |

### 8.1 时序约束

```
set_position → gun_fire → block_clearance → touchdown₁ → midstance₁ → toe_off₁ → swing_peak₁
                                          → touchdown₂ → ... → finish
```

**约束**：`midstance` 必须位于其 `touchdown` 与 `toe_off` 之间。违反时数据加载必须报错，不得静默接受。

### 8.2 事件的 `side` 属性

| 事件 | `side` |
|---|---|
| `touchdown` / `midstance` / `toe_off` / `swing_peak` | **必须**填 `L` 或 `R` |
| `block_clearance` / `finish` | `L` / `R` / `both` |
| `set_position` / `gun_fire` | `both` |

**`side` 不允许留空。** 留空会导致分侧统计全部无法进行，而左右对称性是最有价值的短跑指标之一。

## 9. ID 命名规范

### 9.1 通用格式

```
<前缀>_<主体>[_<限定>]
```

全小写，下划线分隔，**英文**。禁止拼音、大小写混用、缩写（白名单见 §9.4）。

### 9.2 ID 前缀表

| 类型 | 格式 | 示例 |
|---|---|---|
| 队伍 | `t_<短名>` | `t_sportschool_a` |
| 用户 | `u_<序号>` | `u_00012` |
| 运动员 | `at_<序号>` | `at_00007` |
| 采集场次 | `s_<yyyymmdd>_<athlete>_<seq>` | `s_20260301_at00007_01` |
| 分析记录 | `a_<session>_v<n>` | `a_s_20260301_at00007_01_v2` |
| 指标 | 语义化英文，全局唯一 | `shank_angle_touchdown` |
| 视角 | 固定枚举 | `side` |
| 阶段 | 固定枚举 | `acceleration` |
| 事件 | 固定枚举 | `touchdown` |
| 规则 | `R_<视角><阶段>_<问题>` | `R_SIDE_ACC_TRUNK_TOO_UPRIGHT` |
| 处方 | `D_<三位序号>` | `D_007` |
| 结论 | `f_<四位序号>` | `f_0001` |

### 9.3 指标 ID 构词法

```
<被测量的量>[_<限定条件>][_<时刻>]
```

| 示例 | 拆解 |
|---|---|
| `knee_angle` | 基础量 |
| `knee_angle_touchdown` | 基础量 + 时刻 |
| `shank_angle_touchdown` | 量（相对垂直轴）+ 时刻 |
| `pelvis_tilt` | 额状面量 |
| `step_frequency` | 频次量 |

**规则**：
- 角度类统一用 `angle`，不用 `inclination` / `tilt` / `degrees`
- 时刻统一用事件 ID 作后缀（`_touchdown` / `_toeoff` / `_midstance`）
- 区间量用 `_range`，峰值用 `_peak`，均值用 `_mean`

### 9.4 缩写白名单

| 缩写 | 全称 |
|---|---|
| `com` | center of mass（质心） |
| `fps` | frames per second |
| `rsi` | reactive strength index |
| `sd` | standard deviation |
| `cv` | coefficient of variation |

**白名单之外的缩写一律禁止。**

## 10. 版本策略

### 10.1 五套版本号

| 版本字段 | 作用域 | 何时递增 | 存放位置 |
|---|---|---|---|
| `schema_version` | 数据契约结构 | 字段增删改 | 每个响应 |
| `algo_version` | 指标计算算法 | 公式、平滑参数、补偿算法变化 | 每条 Analysis |
| `model_version` | 姿态模型权重 | 换模型或重训 | 每条 Analysis |
| `rule_version` | 规则库 | 阈值调整或规则增删 | 每条 Finding |
| `std_version` | 标准值库 | 参考值更新 | 每个 ref |

### 10.2 版本号格式

统一语义化版本 `MAJOR.MINOR.PATCH`：

| 位 | 递增条件（以 algo 为例） |
|---|---|
| MAJOR | 公式语义变化（如胫骨角从"相对垂直"改为"相对水平"） |
| MINOR | 新增指标，或流程变化但不改变已有指标语义 |
| PATCH | 参数微调（如平滑窗口 25 → 27） |

### 10.3 复合口径标识

报告中向教练展示的是复合标识：

```
分析口径 2026.03.1
  algo  1.4.2
  model yolo11m-pose-v3
  rule  2.1.0
  std   2026Q1
```

**用途**：教练问"为什么这次数据和上次不一样"，看这个就能定位到是哪一套变了。

### 10.4 版本变更后的处理矩阵

| 变更的版本 | 历史数据是否需重算 | 报告是否需重新生成 |
|---|---|---|
| `schema_version` | 否 | 否 |
| `algo_version` | **是** | 是 |
| `model_version` | **是** | 是 |
| `rule_version` | 否 | **是** |
| `std_version` | 否 | **是** |
