# 01 · 术语与命名规范

更新：2026-10-16。本文描述当前实现；未来工作明确标为待完成。

## 术语与层次

Session 是采集场次，Pose 是逐帧关键点，Metric 是测量结果，Finding 是规则判定。测量事实与解释分开；模型置信度、质量码、方法等级、可用于判断的 reliable 布尔值不能互相替代。左右始终以运动员自身为准。

## 当前枚举

单一来源为 [common.schema.json](../backend/contracts/common.schema.json)，Dart 枚举由工具生成。人工请求事件的 left/right 与报告的 L/R 是不同层次的编码，不可直接混用。

| 类型 | 取值 |
|---|---|
| `View` | `side`, `front`, `back` |
| `Phase` | `set`, `start`, `acceleration`, `transition`, `max_velocity`, `deceleration`, `whole_run` |
| `Event` | `set_position`, `gun_fire`, `block_clearance`, `touchdown`, `midstance`, `toe_off`, `swing_peak`, `finish` |
| `Side` | `L`, `R`, `both` |
| `QualityCode` | `0`, `1`, `2` |
| `Reliability` | `A`, `B`, `C` |
| `Severity` | `major`, `minor`, `info`, `insufficient_data` |
| `InsufficientReason` | `low_frame_rate`, `view_mismatch`, `no_reference_scale`, `camera_motion`, `occlusion`, `missing_event`, `perspective_error`, `frame_rate_unverified`, `insufficient_samples`, `insufficient_cycles`, `no_athlete_height`, `implausible_value`, `contact_timing_unreliable`, `not_implemented` |
| `RefSource` | `literature`, `team`, `global` |
| `FpsVerifyStatus` | `verified`, `warning`, `rejected` |

`whole_run` 在人工计时中表示“所选区间（未分期）”，不证明包含完整比赛。`complete_run` 是另一个独立的采集确认。

## 关键点集合

固定 16 点，顺序来自 [pose_types.py](../backend/analysis/pose_types.py)：

```text
head, neck, shoulder_r, hip_r, knee_r, ankle_r, heel_r, toe_r,
shoulder_l, hip_l, knee_l, ankle_l, heel_l, toe_l,
pelvis_center, shoulder_center
```

坐标原点左上，x/W、y/H；q=0 不可见、1 存疑、2 清晰。YOLO 推导的足部点上限为存疑；RTMPose 足部点是模型预测，不能称为仪器实测真值。人工计时不生成姿态。

## 版本与命名

内部 ID、metric_id、事件名使用契约中的稳定英文标识，界面用中文名。App version 与 schema/model/algo/rule/std 版本分别管理，模型版本记录真实配置。新增阶段值后需同步生成模型并检查旧数据兼容性。
