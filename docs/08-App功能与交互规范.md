# 08 · App 功能与交互规范

| 项 | 值 |
|---|---|
| 文档版本 | 2.0.0 |
| 状态 | 已冻结 |
| 形态 | 安卓 App（Flutter） |
| 核心命题 | **让"不确定性"可见，让"下一步该做什么"一目了然** |

---

## 1. App 的定位

> **App 只做四件事：选择文件、读取元数据、填写信息、上传与展示。**
>
> **不做任何分析计算。**

| 理由 | 说明 |
|---|---|
| 视频帧数太多 | 10 秒 240fps = 2400 帧，手机端全流程推理会发热降频 |
| 模型必须能迭代 | 嵌在 App 里意味着每次改模型都要重新发版 |
| 分析是异步的 | 30–90 秒出结果完全可接受 |
| 一人开发 | 端侧 + 服务端两套推理链路会翻倍工作量 |

**App 不做的还有：不在 App 内拍摄。** 视频由用户用系统相机或其他设备录好后导入。

---

## 2. 信息架构

```
首页
├─ 我的运动员              ← 高频：按人查看
├─ 快速上传                ← 高频：拍完立刻传
└─ 待处理（n）              ← 上传中 / 分析中的任务

上传流程
├─ ① 选择视频
├─ ② 元数据校验与提示
├─ ③ 填写采集信息
└─ ④ 上传（后台，可离开）

运动员页
├─ 最近一次分析（结论摘要）
├─ 关键指标趋势图
└─ 历史场次列表

报告页
├─ 头部：运动员 / 日期 / 视角 / 拍摄质量分 / 分析口径
├─ 总览：一句话结论 + 改进项数量
├─ 关键帧图解：原图 + 骨架 + 角度弧线 + 尺度条
├─ 指标对比：本人数值 vs 标准区间
├─ 指导解析：≤3 条，每条含机制 + 处方
└─ 附录：置信度说明 / 拍摄质量 / 帧率校验 / 局限性
```

**任何功能距离首页不超过 3 次点击。**

理由：教练在训练场边的注意力窗口很短。超过 3 层的功能实际上不会被使用。

## 3. 上传流程（核心流程）

### 3.1 第一步：选择视频

| 来源 | Android 实现 |
|---|---|
| 相册 / 文件 | `ACTION_OPEN_DOCUMENT`（SAF） |
| 其他 App 分享 | `ACTION_SEND` Intent Filter |
| 云盘 / U 盘 | SAF 已覆盖 |

**SAF 的好处**：拿到的是 `content://` URI，不需要存储权限，Android 10+ 无需申请 `READ_EXTERNAL_STORAGE`。

### 3.2 第二步：元数据读取与初级校验

App 端必须读取并在界面上展示：

| 字段 | 来源 |
|---|---|
| 时长 | 视频流元数据 |
| 分辨率 | 视频流元数据 |
| 帧数 | 视频流元数据（可能缺失） |
| 声明帧率 | 视频流元数据（**可能缺失**） |
| 编码格式 | 视频流元数据 |
| 文件大小 | 文件系统 |

> ⚠️ **实现注意**：常见的视频元数据读取接口**不提供帧率**。需要读取视频轨的格式信息来获取帧率与帧数属性。这两个属性在某些文件中可能不存在。

**缺失时的处理**：标记为"帧率未知"，交由服务端判定，**不阻塞上传**。

### 3.3 第三步：校验结果的分级提示

| 情况 | 级别 | 处理 |
|---|---|---|
| 无法解码 | **硬拦截** | 不上传 |
| 时长 < 3 秒 | **硬拦截** | 请重新选择 |
| 时长 > 60 秒 | **硬拦截** | 提示只上传需要的片段 |
| 无法读取帧率 | 软提示 | 可继续，服务端会判定 |
| 帧率元数据自相矛盾 | **软警告** | 可继续 |
| 声明帧率 < 120 | **软警告** | 可继续，告知后果 |
| 分辨率 < 1080p | 软警告 | 可继续 |

**校验逻辑（App 端能做的）：**

```
声明帧率 × 时长(秒) ≈ 帧数     → 自洽
偏差 > 20%                    → 警告"帧率元数据可疑"
```

> 这是**变速导出的典型症状**：慢动作视频导出后，帧率写 30 而帧数却是高帧率的量。

### 3.4 软警告的文案要求

**必须写清楚后果，并给出"仍然上传"的选项。**

```
┌─────────────────────────────────────────┐
│  ⚠ 该视频声明帧率为 30 fps                │
│                                          │
│  低于时间类指标要求的 120 fps。            │
│  以下指标将无法计算：                      │
│    · 触地时间                             │
│    · 腾空时间                             │
│    · 占空比                               │
│                                          │
│  角度类指标（膝角、躯干前倾等）不受影响。    │
│                                          │
│  建议：用手机的「慢动作」模式重拍          │
│                                          │
│      [仍然上传]      [换个视频]            │
└─────────────────────────────────────────┘
```

**这样做的两个作用**：提前告知，以及**教育教练下次该怎么拍**。

### 3.5 第四步：填写采集信息

> **只问用户知道的，不问用户不知道的。**

| ❌ 会问错的问题 | ✅ 应该这样问 |
|---|---|
| "请填写像素米比" | "画面里有几条分道线？" → 服务端据此算 |
| "镜头光轴偏角是多少度？" | "拍摄方位是？" → 侧 / 正 / 背 |
| "是否做过畸变校正？" | 不问。服务端按设备与标定档案判断 |
| "相机俯角？" | 不问 |

**用户不知道的字段，问了只会得到乱填的值——而乱填的值比空值更危险。**

#### 表单字段

| 问题 | 类型 | 必填 | 帮助文案 |
|---|---|---|---|
| 运动员 | 选择 / 新建 | ✅ | — |
| **拍摄方位** | **侧面 / 正面 / 背面** | ✅ | **见下方专项设计** |
| 测试类型 | 起跑 / 加速段 / 途中跑 | ✅ | — |
| 相机到跑道距离 | 数字（米） | ✅ | "建议 10 米；不确定可填估计值" |
| 相机高度 | 数字（米） | ✅ | "镜头离地高度，建议与髋同高（约 1.2 米）" |
| **画面中能否看到跑道分道线** | **能 / 不能 / 不确定** | ✅ | "分道线用于换算实际尺寸，能看到会显著提高精度" |
| 镜头是否跟随移动 | 是 / 否 | ✅ | "拍摄过程中镜头有没有跟着运动员转动" |
| 曝光是否锁定 | 是 / 否 / 不确定 | ⭕ | — |
| 运动员身高 | 数字（cm） | ⭕ | "用于体型归一化，建议填写" |

**"不确定"必须是合法选项。** 逼用户猜会得到错误数据；允许"不确定"则服务端可按最坏情况处理。

#### 「拍摄方位」的专项设计 ⚠️

**这是最重要的一个表单字段**，因为它直接决定计算哪些指标。必须用**图示 + 文字**双重表达，不能只给三个选项。

```
┌─────────────────────────────────────────┐
│  拍摄方位                                 │
│                                          │
│  ┌────┐   ┌────┐   ┌────┐               │
│  │ 🏃 │   │ 🏃 │   │ 🏃 │               │
│  │ ←  │   │ ↓  │   │ ↑  │               │
│  └────┘   └────┘   └────┘               │
│   侧面      正面      背面                │
│                                          │
│  侧面：镜头在跑道旁边，拍到运动员的侧身     │
│  正面：镜头在运动员前方，拍到他迎面跑来     │
│  背面：镜头在运动员后方，拍到他跑远         │
│                                          │
│  ℹ 不同方位能分析的指标不同：              │
│    侧面 → 关节角度、躯干前倾、步幅          │
│    正面/背面 → 骨盆控制、膝内扣、着地宽度    │
└─────────────────────────────────────────┘
```

**为什么需要图示**：教练不是工程师，"侧面/正面/背面"这三个词在没有图示时的理解差异很大。

### 3.6 第五步：上传

| 项 | 要求 |
|---|---|
| 分片大小 | 5–10 MB |
| 并发分片 | 2–3（避免抢占带宽） |
| 断点续传 | 记录已完成分片，重连后续传 |
| 后台继续 | 前台服务 + 通知 |
| 单分片超时 | 60 秒 |
| 失败重试 | 指数退避，最多 5 次 |
| **转码 / 压缩** | **禁止** |

**体积估算**：1080p@240fps，10 秒约 80–150 MB。这个量级必须支持后台续传，否则用户会一直盯着进度条。

**必须支持**：上传过程中切后台、接电话、断网，恢复后继续。

## 4. 三种数据状态的视觉语言 ⚠️

> **本节是全套 App 规范中最重要的部分。**

系统必须让"不确定性"可见。这是专业工具与玩具的分界线。

### 4.1 四种状态

| 状态 | 判定条件 | 视觉处理 |
|---|---|---|
| **正常** | `reliable: true` 且 `q ≥ 1` 且 `is_interpolated: false` | 实线、标准色、正常字重 |
| **低置信** | `reliable: false` 或 `confidence < 0.7` | 虚线、降饱和、数值后加 `?` |
| **插值补出** | `is_interpolated: true` | 虚线、半透明、不可交互 |
| **数据不足** | `insufficient != null` | 灰色占位块 + 原因 + 改进建议 |

### 4.2 禁止做法

| 禁止 | 后果 |
|---|---|
| 隐藏不可靠指标 | 教练怀疑数据被挑选过 |
| 把插值点画成实线 | 教练以为看到了实测，实际是模型猜的 |
| 用同一视觉呈现不同确定性 | 教练无法分辨哪些数字可信 |
| 数据不足时显示 0 或空 | 被理解为"没问题"或"系统故障" |

### 4.3 视觉具体化

```
正常
  着地胫骨角   12.4°   ▓▓▓▓▓░░░░░  [标准区间 8–15°]

低置信
  触地时间     183 ms?  ▓▓▓░░░░░░░  [标准区间 160–220 ms]
  ⚠ 素材帧率 60fps，该指标误差可能超过 20%

视角不匹配
  ┌─────────────────────────────────────┐
  │ 着地膝内扣角            ——           │
  │ 需要：正面或背面视角                  │
  │ 当前：侧面视角                        │
  │ 建议：从运动员正前方或正后方补拍        │
  └─────────────────────────────────────┘

数据不足
  ┌─────────────────────────────────────┐
  │ 步幅                    ——           │
  │ 原因：缺少参考尺度                    │
  │ 要求：画面中可见 ≥2 条分道线           │
  │ 建议：拍摄时让跑道分道线入画            │
  └─────────────────────────────────────┘
```

## 5. 设计令牌

### 5.1 颜色

```
/* 状态色 */
--color-normal        #2E7D32    正常
--color-warning       #F57C00    偏离但轻微
--color-critical      #C62828    显著偏离
--color-insufficient  #9E9E9E    数据不足
--color-ref-zone      #E3F2FD    标准区间底色

/* 骨架叠加（侧面） */
--color-skeleton-near #FFEB3B    近侧肢体
--color-skeleton-far  #9E9E9E    远侧肢体（半透明）

/* 骨架叠加（正面/背面） */
--color-skeleton-right #FF6D00   运动员右侧
--color-skeleton-left  #2979FF   运动员左侧

/* 基础色 */
--color-bg            #FFFFFF
--color-surface       #F5F5F5
--color-text-primary  #212121
--color-text-secondary #616161
--color-divider       #E0E0E0
```

**为什么要分两套骨架配色**：

| 视角 | 需要分辨的 | 配色依据 |
|---|---|---|
| 侧面 | 近侧腿 vs 远侧腿 | 黄色实线 / 灰色虚线 |
| 正面/背面 | 运动员左腿 vs 右腿 | 左右不同色 |

### 5.2 字号

```
--font-metric-value   32px / 600    指标数值
--font-metric-label   16px / 500    指标名
--font-title          20px / 600    区块标题
--font-body           15px / 400    正文
--font-caption        14px / 400    注释与免责
```

**最小字号 14px。**

理由：教练常在户外强光下、戴着手套、或训练后疲劳状态下使用。

### 5.3 间距与圆角

```
间距   8 的倍数：8 / 16 / 24 / 32 / 48
圆角   8px（卡片）/ 4px（标签）
阴影   0 2px 4px rgba(0,0,0,0.08)  仅用于浮动卡片
```

## 6. 报告页设计

### 6.1 首屏必须包含

> **教练打开报告，不滚动就应该看到"该改什么"。**

| 元素 | 位置 |
|---|---|
| 一句话结论 | 顶部，字号最大 |
| 改进项数量 | 紧随其后 |
| **视角标签** | 右上角（侧 / 正 / 背） |
| 拍摄质量分 | 右上角小字 |
| 第一条建议的标题 | 首屏底部 |

### 6.2 关键帧图解

| 元素 | 要求 |
|---|---|
| 骨架叠加 | 侧面：近侧实线黄 / 远侧虚线灰；正背面：左右不同色 |
| 关节点 | 正常实心；`q=1` 空心；`q=0` 不绘制 |
| 角度弧线 | 在对应关节绘制，标注角度值 |
| **尺度条** | **必须绘制**，见下方说明 |
| 事件标签 | 事件中文名 + 步次 + 阶段 |
| 视角标签 | 标明视角 |

#### 尺度条的必要性 ⚠️

跟踪拍摄下，同一段视频中不同帧的运动员像素尺寸不同。**如果不标注尺度，教练会误以为"这个人变大了"。**

```
┌──────────────────────────────────────┐
│  着地 (touchdown) · 第 2 步 · 加速段   │
│  ┌────────────────────────────────┐  │
│  │                                │  │
│  │      [原图 + 骨架 + 角度弧线]    │  │
│  │                                │  │
│  │  胫骨角 12.4°  膝角 158.2°      │  │
│  └────────────────────────────────┘  │
│  ├────┤ 0.5 m          侧面视角        │
└──────────────────────────────────────┘
```

**每张关键帧图必须画一条比例尺**，标注该帧的实际尺度。

### 6.3 指标对比区

横向条形图，每行一个指标：

```
着地胫骨角        12.4°   ├────▓────┤      标准 8–15°    ✓
着地膝角         158.2°   ├──▓──────┤      标准 150–178° ✓
躯干前倾角        38.2°   ├▓────────┤      标准 45–60°   ⚠
触地时间         183 ms?  ├──▓──────┤      标准 160–220  ⚠
```

| 元素 | 说明 |
|---|---|
| 标准区间 | 浅蓝底色条 |
| 本人数值 | 圆点标记 |
| 判定 | 右侧符号 `✓` / `⚠` / `?` |
| 队内均值（若可用） | 竖线标记 |

**不显示标准化偏离值给教练看。** 那是给规则引擎用的中间量，教练看不懂也不需要懂。界面只回答"在不在区间内"。

**视角分组的处理**：侧面与额状面指标**分组显示**，并标明各自的视角来源。

### 6.4 指导解析区

```
┌─────────────────────────────────────────┐
│ ● 加速段躯干过早直立                      │
│                                          │
│   实测 38.2°，该阶段应有 45–60°           │
│                                          │
│   加速段躯干前倾角不足，说明身体过早抬起，   │
│   会缩短水平推进的有效做功距离。            │
│                                          │
│   建议练习                                │
│   ┌───────────────────────────────────┐ │
│   │ 推墙加速跑                         │ │
│   │ 4 组 × 8 次 · 组间 90 秒           │ │
│   │ 口令：保持躯干前倾，让身体呈一条斜线 │ │
│   └───────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

**结构固定**：标题 → 实测值与标准 → 机制解释 → 处方。

## 7. 状态设计

### 7.1 分析进行中

分析可能耗时 90 秒。只显示转圈会让用户以为卡死。

```
正在分析
━━━━━━━━━━━━━━━░░░░░░░░░░  55%

✓ 视频解码
✓ 帧率校验
✓ 镜头运动检测
✓ 视角校验
✓ 畸变校正
✓ 参考尺度标定
◐ 姿态提取
○ 时序平滑
○ 有效帧判定
○ 事件识别
○ 阶段切分
○ 指标计算
○ 生成报告
```

**分阶段进度必须暴露。** 这不仅改善感知，也让失败时能定位到具体阶段。

### 7.2 失败状态

| 要求 | 说明 |
|---|---|
| 显示失败原因 | 不只是"失败" |
| 给出可操作建议 | 告诉用户下一步做什么 |
| 区分可恢复与不可恢复 | 可恢复的提供重试按钮 |

```
✗ 帧率校验未通过

三种校验方法的偏差达 22%，超过 15% 的容忍上限。
可能原因：视频经过变速处理，或容器帧率信息错误。

建议：确认导出视频为原始帧率，未经剪辑软件变速处理。

[重新上传]  [仅分析角度指标]
```

```
✗ 视角无法确认

你选择了「侧面」，但检测到骨盆投影宽度接近肩宽，
判断为正面或背面视角。

[改成正面]  [改成背面]  [确实是侧面]
```

### 7.3 空状态

每个空状态都必须说明**下一步该做什么**。

| 页面 | 空状态文案 |
|---|---|
| 运动员列表 | "还没有运动员。点击右上角添加，或直接开始快速上传。" |
| 历史场次 | "还没有分析记录。去上传页选一段视频开始。" |
| 趋势图 | "数据不足，至少需要 2 次测试才能显示趋势。" |

## 8. 交互规范

### 8.1 加载与响应

| 操作 | 最大等待 | 超时处理 |
|---|---|---|
| 页面切换 | 300 ms | 骨架屏 |
| 数据请求 | 2 s | 显示加载态 + 可取消 |
| 上传 | 无上限 | 后台继续，可离开页面 |
| 分析 | 180 s | 转后台，完成后推送通知 |

### 8.2 手势

| 手势 | 行为 | 适用 |
|---|---|---|
| 左右滑动 | 切换关键帧 | 关键帧回放区 |
| 双指缩放 | 放大骨架图 | 关键帧图 |
| 长按 | 显示指标详情 | 指标行 |

### 8.3 离线行为

| 状态 | 行为 |
|---|---|
| 无网络 | 已缓存的报告可读；上传排队 |
| 弱网 | 上传自动降低并发分片数；已上传分片不重传 |
| 恢复 | 自动继续上传，不打断用户操作 |

## 9. 无障碍与场景适配

| 场景 | 设计要求 |
|---|---|
| 户外强光 | 对比度 ≥ 4.5:1；不依赖颜色单独传达信息 |
| 戴手套 | 点击目标 ≥ 48×48 px |
| 单手操作 | 主要操作集中在屏幕下半部 |
| 疲劳状态 | 关键信息字号 ≥ 16 px |
| **色觉障碍** | **状态除颜色外必须有符号**（✓ / ⚠ / ? / ——） |

> **最后一条是硬要求**：红绿色盲在男性中约占 8%。状态判定**不得仅依赖颜色**。

## 10. 文案规范

### 10.1 术语的用户化对照

| 系统术语 | 界面文案 |
|---|---|
| `insufficient_data` | 数据不足，无法评估 |
| `view_mismatch` | 该指标需要另一种拍摄方位 |
| `no_reference_scale` | 缺少参考尺度 |
| `camera_motion` | 镜头移动导致该指标不可靠 |
| `perspective_error` | 运动员偏离画面中心过远 |
| `reliable: false` | 结果仅供参考 |
| `low_frame_rate` | 拍摄帧率不够 |
| `is_interpolated` | 该点为推算补出 |

### 10.2 禁止文案

| 禁止 | 原因 |
|---|---|
| "数据异常" | 无信息量，用户不知道怎么办 |
| "操作失败" | 不说明原因 |
| "暂无数据" | 不说明为什么没有、该怎么办 |
| 任何技术术语 | `z-score`、`JSON`、`null`、`timeout`、`fps_declared` |

### 10.3 语气

| 要求 | 示例 |
|---|---|
| 描述动作，不评价人 | ✅ "着地点偏前" ❌ "你的跑姿有问题" |
| 给方向，不给结论 | ✅ "该阶段应有 45–60°" ❌ "太差了" |
| 可执行 | ✅ "改用慢动作模式重拍" ❌ "数据质量不佳" |
