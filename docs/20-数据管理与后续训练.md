# 数据管理与后续训练

更新：2026-10-16。

## 当前自动保存的范围

成功的人工标注或显式框选任务保存到项目目录data/manual_timing/<job_id>/，保留原视频副本、review.json（运动员ID/姓名、任务/视频ID、人工确认、事件、选人信息和来源）及report.json。自动模式另存target_tracking.json。这个目录名沿用早期人工计时，不能据目录名推断所有记录都是人工标签。

失败的自动跟踪不生成成功报告、不进成功数据集，诊断轨迹位于.cache/keyframes/<job_id>/target_tracking.json。未带人工/框选参数的旧API任务不保证进入此归档。

临时上传在.cache/uploads，按24小时清理；任务与上传映射在内存，重启服务后不能由App自动恢复它们。成功归档不受该24小时策略清理。当前并未实现所有失败/取消上传的永久保留或完整数据库同步。

## 备份与隐私

数据集、私有视频、账号和缓存不入GitHub。请对data/manual_timing及.cache/accounts.json独立备份；output可能包含唯一调研与人工核对产物，清理前也应确认。删除整个.cache会丢账号及未归档上传，不能把.gitignore理解为可安全删除清单。用户授权、用途、保留时间及删除请求需在后续数据治理中明确，当前没有完整管理界面。

## 如何用于改进

先区分人工事件、模型预测与独立审核真值。review中的人工确认不等于已通过双人或仪器验证。建议后续增加匿名运动员标识、场次、拍摄设备/曝光/真实帧率、复核者、标签版本及授权记录；这些是待实现字段，当前并未全部采集。

按运动员和场次拆分训练/验证/测试，避免同一视频相邻帧跨集合。时间事件用于自动接触检测；人物框和轨迹经复核后用于检测/关联；姿态微调需要额外人工关键点，现有事件标注不能直接替代关键点标签。先建立基线，测漏检、身份切换、提前中断与接触毫秒误差，再决定训练方案。

标准库只接收经审核的人群与口径一致统计，不能把模型预测批量变成标准。建议库还需干预依据和效果复核。当前没有自动训练、自动替换模型或自动修订标准库。
