# 07 · 数据契约

更新：2026-10-16。本文描述当前实现；未来工作明确标为待完成。

## 版本策略

报告 schema_version=1.2.0；枚举由 [common.schema.json](../backend/contracts/common.schema.json) 定义，完整结构见 [contracts](../backend/contracts)。新增 whole_run 后同步 Dart 枚举，人工计时中含义是所选未分期区间。请求协议与报告结构分别管理，不能将下述请求字段当作报告Schema字段。

## 当前服务接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/health | 连接与服务版本 |
| POST | /api/videos | 原始视频字节上传，返回video_id |
| GET | /api/videos/<video_id>/metadata | 原片时间基准及帧数检查 |
| GET | /api/videos/<video_id>/frames/<index> | 原始帧预览，JPEG95 |
| POST | /api/analyze | 提交分析，返回job_id |
| GET | /api/jobs/<job_id> | 任务进度与完成报告 |
| GET | /api/reports/<job_id> | 报告JSON |
| POST | /api/auth/register、/api/auth/login | 账号注册与登录 |
| POST | /api/profile、/api/redeem、/api/admin/codes | 资料、兑换及管理原型接口 |

上传不是multipart，video_id由服务生成，为16位十六进制；不接受任意本机视频路径。关键帧使用服务返回的keyframes地址。具体状态码、可选字段及错误体以 [app.py](../backend/server/app.py) 和 [客户端](../mobile/lib/data/analysis_server_client.dart) 为准，尚没有完整OpenAPI定义。

## 人工分析请求

除video_id、username、运动员/采集信息外：

```json
{
  "analysis_mode": "manual_side_v1",
  "view": "side",
  "camera_followed": false,
  "target_selection": {
    "protocol": "athlete_lock_v1", "frame": 0, "end_frame": 120,
    "bbox": [0.2, 0.1, 0.6, 0.9], "confirmed": true
  },
  "manual_review": {
    "protocol": "manual_side_v1",
    "original_cfr_confirmed": true, "fixed_side_confirmed": true,
    "same_athlete_confirmed": true, "all_contacts_confirmed": true,
    "events": [
      {"frame": 0, "side": "left", "type": "touchdown"},
      {"frame": 24, "side": "left", "type": "toe_off"},
      {"frame": 48, "side": "right", "type": "touchdown"},
      {"frame": 72, "side": "right", "type": "toe_off"}
    ]
  }
}
```

示例只展示协议片段，素材需满足高帧率且至少121帧。target_selection使用完整原图归一化[x1,y1,x2,y2]，不含预览留白；起止零起始且两端包含。事件请求用left/right，报告侧别用L/R。事件必须在选定区间。

## 校验与兼容

人工、选人和模型参数在扣额度前校验。分析运行失败沿用现有额度机制，无自动退款。任务状态queued/running/done/failed，任务和上传映射未持久化。

不可用指标使用null与insufficient说明，不能用0代替；模型配置写versions.model_version。参考匹配额外字段见 [17](17-参考值严格匹配.md)。尚未实现通用姿态分页、人工结果在线修订与持久任务恢复等旧设计接口。
