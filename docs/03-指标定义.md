## 1. 角度定义统一约定

> **所有角度遵循同一套约定，不得有例外。**

### 1.1 约定一：线段角 —— 一律相对参考轴

```
0°  = 与参考轴重合
正值 = 上端（或远端）位于参考方向的正侧
负值 = 相反侧
```

| 平面 | 参考轴 | 正方向 |
|---|---|---|
| 矢状面（侧面） | 垂直轴 | 向跑动方向前方 |
| 额状面（正/背面） | 垂直轴 | 向运动员自身右侧 |

### 1.2 约定二：关节角 —— 三点夹角，顶点居中

```
knee_angle   = 顶点在 knee  的 ∠(hip, knee, ankle)
hip_angle    = 顶点在 hip   的 ∠(shoulder, hip, knee)
ankle_angle  = 顶点在 ankle 的 ∠(knee, ankle, toe)
```

**参数顺序必须是 `(上端, 下端)`，顶点在中间。** 顺序写反不会报错，只会静默返回错误的值。

### 1.3 约定三：线段角必须用 `atan2`，不得用 `arccos` ⚠️

`arccos` 会丢失符号信息，返回补角。

```python
def segment_angle_from_axis(upper, lower, axis='vertical', forward_sign=+1):
    """
    upper, lower : (x, y) 像素坐标，y 轴向下
    forward_sign : 侧面视角下跑动方向为画面左→右时取 +1
                   正/背视角下运动员右侧为画面右侧时取 +1
    返回：相对参考轴的夹角
    """
    dx = upper[0] - lower[0]          # 正值 = 上端在右侧（画面）
    dy = lower[1] - upper[1]          # 正值 = 上端在上方
    if abs(dx) < 1e-9 and abs(dy) < 1e-9:
        return None
    return forward_sign * degrees(atan2(dx, dy))
```

**关节角用 `arccos` 是安全的**（三点夹角对 y 轴翻转不变）。**线段角必须用 `atan2`。**

### 1.4 四象限验算用例（必须实现为测试）

| 场景 | upper | lower | 期望 |
|---|---|---|---|
| 完全垂直 | (100, 0) | (100, 100) | 0° |
| 上端在右 45° | (200, 0) | (100, 100) | +45° |
| 上端在左 45° | (0, 0) | (100, 100) | −45° |
| 上端在右下 | (200, 200) | (100, 100) | +135° |
| 上端在左下 | (0, 200) | (100, 100) | −135° |
| 水平向右 | (200, 100) | (100, 100) | +90° |
| 两点重合 | (100, 100) | (100, 100) | `None` |

## 2. 视角与指标的绑定 ⚠️

> **视角不是元数据，是决定计算内容的参数。**

| 视角 | 可计算 | **不可计算** |
|---|---|---|
| `side` | 矢状面角度、时间类、步幅 | 额状面指标 |
| `front` / `back` | 额状面指标、时间类、对称性 | **所有矢状面角度** |

**请求的指标与视角不匹配时，返回 `insufficient_data`，原因 `view_mismatch`。不得用另一视角的数据代替。**

### 2.1 时间类指标是唯一跨视角通用的

`step_frequency` / `ground_contact_time` / `flight_time` / `duty_factor` 只依赖帧号与足部与地面的相对位置，**三种视角都可用**。

## 3. 指标目录（按视角分类）

### 3.1 跨视角通用（时间类）

| # | metric_id | 中文 | 单位 | min_fps | 可靠性 |
|---|---|---|---|---|---|
| 1 | `step_frequency` | 步频 | 步/分 | 60 | A |
| 2 | `ground_contact_time` | 触地时间 | ms | **120** | A |
| 3 | `flight_time` | 腾空时间 | ms | **120** | A |
| 4 | `duty_factor` | 占空比 | — | **120** | A |

**计算式**

```
step_frequency = 60000 / (同侧相邻 touchdown 帧差 / fps_verified × 1000)

ground_contact_time = (toe_off.frame - touchdown.frame) / fps_verified × 1000
                     其中 touchdown 与 toe_off 必须同侧、且 toe_off 在 touchdown 之后

flight_time = (下次 touchdown.frame - 本次 toe_off.frame) / fps_verified × 1000

duty_factor = ground_contact_time / (ground_contact_time + flight_time)
```

**实现要点**
- `fps_verified` 必须是校验后的帧率，不得使用容器声明值
- 触地时间必须**配对**：一个 `touchdown` 只与紧随其后、同侧的 `toe_off` 配对。配对失败则该步次作废
- 步频取同侧相邻着地间隔；不同侧的间隔是半步，不可混用
- **镜头跟踪不影响这些指标**（只依赖帧号）

### 3.2 侧面视角 · 矢状面角度

| # | metric_id | 中文 | 单位 | event | min_fps | 可靠性 |
|---|---|---|---|---|---|---|
| 5 | `shank_angle_touchdown` | 着地胫骨角 | deg | `touchdown` | 60 | A |
| 6 | `knee_angle_touchdown` | 着地膝角 | deg | `touchdown` | 60 | A |
| 7 | `knee_angle_midstance` | 支撑中期膝角 | deg | `midstance` | 60 | A |
| 8 | `hip_angle_toeoff` | 离地髋角 | deg | `toe_off` | 60 | A |
| 9 | `trunk_lean` | 躯干前倾角 | deg | 逐帧 | 60 | A |
| 10 | `thigh_swing_range` | 大腿摆动幅度 | deg | 摆动期 | 60 | B |
| 11 | `ankle_angle_touchdown` | 着地踝角 | deg | `touchdown` | 120 | B |

**计算式**

```
shank_angle_touchdown = segment_angle_from_axis(knee, ankle)   @ touchdown
knee_angle_touchdown  = angle(hip, knee, ankle)                 @ touchdown
knee_angle_midstance  = angle(hip, knee, ankle)                 @ midstance
hip_angle_toeoff      = angle(shoulder, hip, knee)              @ toe_off
trunk_lean            = segment_angle_from_axis(neck, hip)      @ 逐帧
thigh_swing_range     = max(thigh角) - min(thigh角) over 摆动期
                        其中 thigh角 = segment_angle_from_axis(knee, hip)
ankle_angle_touchdown = angle(knee, ankle, toe)                 @ touchdown
```

**实现要点**
- 事件帧指标使用**事件标注那一帧的原始坐标**，不使用平滑后坐标（平滑会移动极值位置）
- "摆动期" = 同侧 `toe_off` → 下次同侧 `touchdown`
- **`trunk_lean` 是唯一需要按阶段分别给标准值的指标**，见 §6.2
- 镜头跟踪下这些角度**基本免疫**（角度对像素尺度不敏感），但受透视误差影响，见 §5

### 3.3 侧面视角 · 位移类

| # | metric_id | 中文 | 单位 | min_fps | 需参考尺度 | 可靠性 |
|---|---|---|---|---|---|---|
| 12 | `step_length_relative` | 步幅（相对身高） | — | 60 | 否 | A |
| 13 | `step_length` | 步幅（绝对） | m | 60 | **是** | B |
| 14 | `com_height_oscillation` | 质心垂直振幅 | m | 120 | **是** | C |

**计算式**

```
step_length_relative = (相邻同侧 touchdown 时踝的像素水平距离)
                       / (该运动员的腿长像素中位数)

step_length = 相邻同侧 touchdown 时踝的像素水平距离 / 逐帧 pixels_per_meter

com_height_oscillation = (max(com.y) - min(com.y)) / 逐帧 pixels_per_meter
                         同时输出归一化值（除以身高）
```

**实现要点**

> **跟踪拍摄下，绝对速度与绝对质心位移不可输出。**

| 指标 | 状态 | 原因 |
|---|---|---|
| `step_length_relative` | ✅ 可用 | 用运动员自身腿长做参考，不受距离变化影响 |
| `step_length` | ⚠️ 有条件 | 需要逐帧参考尺度（分道线或身高）。**无参考尺度时返回 `insufficient_data`** |
| `com_height_oscillation` | ⚠️ C 级 | 依赖质心模型，本已不准，跟踪下更不可靠 |
| 速度曲线 | ❌ **不输出** | 无法分离镜头运动 |
| 质心绝对位移 | ❌ **不输出** | 同上 |

**这是诚实的能力边界。给一个错的速度数字，比不给速度数字危害大得多。**

### 3.4 正面 / 背面视角 · 额状面指标

| # | metric_id | 中文 | 单位 | 适用视角 | min_fps | 可靠性 |
|---|---|---|---|---|---|---|
| 15 | `pelvis_tilt` | 骨盆倾斜角 | deg | front / back | 60 | B |
| 16 | `pelvis_rotation` | 骨盆旋转角 | deg | front / back | 120 | C |
| 17 | `knee_valgus_touchdown` | 着地膝内扣角 | deg | front / back | 60 | B |
| 18 | `stance_width_relative` | 着地宽度（相对髋宽） | — | front / back | 60 | B |
| 19 | `trunk_lateral_lean` | 躯干侧倾角 | deg | front / back | 60 | B |
| 20 | `pelvis_drop_midstance` | 支撑中期骨盆下沉 | deg | front / back | 60 | B |

**计算式**

```
pelvis_tilt = segment_angle_from_axis(hip_r, hip_l)
              @ 逐帧；正值 = 右侧髋高于左侧

pelvis_rotation = 骨盆宽度在画面中的投影 / 骨盆宽度的中位投影
                  → 换算为旋转角（cos 关系）
                  @ 逐帧；受跟踪与遮挡影响大，故为 C 级

knee_valgus_touchdown = angle(hip, knee, ankle) 在额状面的投影
                        正值 = 膝偏向身体中线内侧（内扣）
                        @ touchdown

stance_width_relative = |着地侧踝的x − 对侧踝的x| / 髋宽像素中位数
                        @ touchdown

trunk_lateral_lean = segment_angle_from_axis(shoulder_center, pelvis_center)
                     正值 = 向右侧倾
                     @ 逐帧

pelvis_drop_midstance = pelvis_tilt @ midstance − pelvis_tilt @ touchdown
                        正值 = 支撑侧髋下沉（Trendelenburg 征象）
```

**实现要点**

- 额状面指标的**左右定义在正/背视角下相反**，必须在代码中显式处理（见 `01-术语与命名规范.md` §4.2）
- `pelvis_rotation` 依赖骨盆宽度的投影变化，**对跟踪拍摄与遮挡极敏感**，故为 C 级，仅用于趋势对比。
  另有一个固有限制：`arccos` **无法区分旋转方向**（前旋与后旋给出同样的投影宽），
  所以该指标只给出幅度、不给出方向，报告里必须讲清
- `knee_valgus_touchdown` 需要区分内扣与外展，**符号定义必须与标准值来源一致**
- 这些指标在侧面视角下**全部返回 `insufficient_data`**，原因 `view_mismatch`

> **勘误（2026-10-05，实现阶段发现）**
>
> 原表把 `stance_width_relative` 归入"需参考尺度"的指标。这是**错的**。
>
> 计算式是 `|着地侧踝x − 对侧踝x| / 髋宽像素中位数` ——
> 分子分母都是画面长度，换算成实际距离时**尺度因子会约掉**。
>
> 更正后：该指标**不需要参考尺度**。实际影响不小 ——
> 它是额状面里少数几个在跟踪拍摄、没有参照物的素材上仍能用的指标，
> 标错会让它在这些场景下被无谓地拦下。

## 4. 质心估算

采用 Dempster / Winter 分段质量模型。

| 环节 | 质量占比 | 质心位置（沿该环节线段） |
|---|---|---|
| 头 + 颈 | 8.1% | 头颈中点 |
| 躯干 | 49.7% | 颈髋连线上，距颈 0.50 |
| 大腿 | 10.0% × 2 | 髋膝连线上，距髋 0.433 |
| 小腿 | 4.65% × 2 | 膝踝连线上，距膝 0.433 |
| 足 | 1.45% × 2 | 踝趾连线上，距踝 0.50 |

```
com = Σ (mass_i × centroid_i) / Σ mass_i
```

### 4.1 已知偏差 ⚠️

> **分段质量参数基于欧美人群数据。亚洲运动员体型差异可能带来系统性偏差。**

**必须执行的验证**：在队内做一次小样本验证（与体成分数据对比）。

**验证前的处理**：所有含质心的指标可靠性**降一级**。

### 4.2 替代方案

若质心精度不可接受，可用**骨盆中心**（两髋中点）作为近似：

- 优点：不依赖分段质量参数，无人群偏差
- 缺点：骨盆中心与真实质心存在随姿态变化的偏移

**采用替代方案时，`metric_id` 必须相应改名（如 `pelvis_height_oscillation`），不得沿用 `com_` 前缀。命名必须反映实际测的是什么。**

## 5. 镜头跟踪的影响与补偿 ⚠️

> **这是本项目区别于其他同类系统的核心处理。**

### 5.1 各指标对镜头跟踪的敏感度

| 指标类别 | 敏感度 | 原因 | 处理 |
|---|---|---|---|
| **时间类** | **无** | 只依赖帧号 | 正常输出 |
| **矢状面/额状面角度** | **低** | 角度对像素尺度不敏感 | 受透视误差限制，见 §5.2 |
| **相对位移**（如步幅/身高） | **低** | 分子分母同尺度 | 正常输出 |
| **绝对位移** | **高** | 像素↔米比例逐帧变化 | 需逐帧参考尺度 |
| **绝对速度** | **致命** | 无法分离镜头运动 | **不输出** |

### 5.2 透视误差

运动员偏离画面中心时视线偏斜，投影到画面的角度 ≠ 真实角度。

| 视线偏斜 | 对 30° 真实角度的误差 |
|---|---|
| 0–10° | < 1° |
| 15° | 约 1° |
| 30° | 3–4° |
| 45° | 6–8° |

**这个误差是系统性的，不会因重复测量而减小。**

**控制手段**：有效测量窗（见 `02-数据标准.md` §5）

| 区域 | 处理 |
|---|---|
| 画面中心 ±20% | 正常 |
| ±20% – ±35% | 置信度乘 0.6 |
| > ±35% | 排除该帧 |

### 5.3 逐帧透视误差估计（必须输出）

每个指标必须输出一个 `perspective_error_estimate`，值为该指标所有有效帧中最大的视线偏斜角对应误差。

```
perspective_error_estimate = max over frames (f(该帧运动员的偏斜角))
```

**用途**：
- 在报告中显示"本次测量受跟踪拍摄影响，误差约 ±X°"
- 当该值 > 3° 时，报告的结论措辞必须降级

### 5.4 有效帧不足的处理

| 情况 | 处理 |
|---|---|
| 某指标有效帧 < 3 | 返回 `insufficient_data`，原因 `perspective_error` |
| 整体有效帧占比 < 50% | 报告横幅提示"跟踪过快，精度受限" |
| 整体有效帧占比 < 25% | 报告横幅提示"建议改用固定机位" |

## 6. 标准值引用规范

### 6.1 铁律

> **任何写入标准值库的数字，必须能指向一份可查证的原始文献，且记录页码或图表号。**
>
> **查不到就留空。留空意味着该指标只输出测量值，不做偏离判断。**

完整流程见 `04-参考标准值规范.md`。

### 6.2 `trunk_lean` 的阶段绑定（重点）⚠️

**这是全套指标中唯一在每个阶段有完全不同标准值的指标，也是误报风险最高的地方。**

| 阶段 | 应有区间（示意，实际值待采集） |
|---|---|
| `start` | 大幅前倾 |
| `acceleration` | **45–60°** |
| `transition` | 递减 |
| `max_velocity` | **5–15°** |
| `deceleration` | 略增 |

> **同一个数字在不同阶段含义相反。**
>
> 加速段躯干前倾 60° 是**优秀表现**；途中跑躯干前倾 60° 是**严重错误**。

**强制规则**：
- `ref.applicable_phase` 与 `metric.phase` 不一致时，**偏离度必须为 `null`**
- 界面**不得**显示偏离判断
- 规则引擎**不得**基于跨阶段标准值触发结论

### 6.3 标准值的三层来源

| 层级 | `ref.source` | 优先级 | 启用条件 | 界面措辞 |
|---|---|---|---|---|
| 文献 | `literature` | 低 | 默认（冷启动） | "超出常见范围（参考值 …）" |
| 队内 | `team` | 高 | 同队累计 ≥30 人次 | "高于本队同水平运动员均值" |
| 全局 | `global` | 中 | 平台累计 ≥500 人次 | "高于同项目运动员均值" |

**教练对队内对比的信任度远高于文献对比，措辞必须不同。**

### 6.4 `sd` 缺失时的处理

```
sd 存在   → 可计算标准化偏离
sd 缺失   → 偏离度输出 null，仅做区间对比（在区间内 / 外）
区间也缺失 → 不做任何偏离判断，只输出测量值
```

**不得用经验值补全缺失的 `sd`。**

## 7. 平滑规范

> **原始姿态输出逐帧抖动可达数个像素。直接求导会让噪声放大十倍以上。**
>
> **平滑必须在求导之前。** 这是本文件中最容易被跳过、后果最严重的一条。

| 用途 | 方法 | 参数 |
|---|---|---|
| 坐标序列（用于速度/位移） | Savitzky-Golay | 窗口 = `round(fps_verified / 10)`，取奇数；阶数 2 |
| 求导（角速度、线速度） | Savitzky-Golay **导数模式** | 同上；**不要先平滑再差分** |
| 事件帧定位与角度计算 | **不平滑**，用原始标注坐标 | 平滑会移动极值位置 |

### 7.1 窗口大小的权衡

| 窗口 | 效果 |
|---|---|
| < fps/20 | 平滑不足，噪声残留 |
| **fps/10** | **推荐** |
| > fps/5 | 过度平滑，峰值被削平 |

**窗口改变即视为 `algo_version` 变更（MINOR 级）**，历史数据需重算。

### 7.2 事件帧不平滑的原因

事件帧指标测的是**该瞬间**的值。平滑会把邻帧信息混入，使极值被削平。

以触地瞬间为例：触地前后膝角变化剧烈，平滑会使触地膝角偏向邻帧均值，产生系统性偏差。

## 8. 数据不足的判定规则

| 条件 | `reason` |
|---|---|
| `fps_verified < min_fps` | `low_frame_rate` |
| 视角与指标不匹配 | `view_mismatch` |
| 需参考尺度但无可用尺度 | `no_reference_scale` |
| 该指标在跟踪拍摄下不可靠 | `camera_motion` |
| 依赖的关键点 `q = 0` | `occlusion` |
| 依赖的事件未标注 | `missing_event` |
| 有效帧（排除 `ambiguous` 与窗外帧）< 3 | `perspective_error` |
| 完整步次 < 3 | `insufficient_samples` |
| 帧率无法校验 | `frame_rate_unverified` |

### 8.1 `reliable: false` 与 `insufficient_data` 的区别

| 状态 | 含义 | 输出 |
|---|---|---|
| 有值，`reliable: true` | 可用于判断 | 数值 + 标准区间对比 + 结论 |
| 有值，`reliable: false` | **能算但不可用于判断** | 数值 + 显式警示，不参与结论 |
| `insufficient_data` | **算不出来** | 无数值 + 原因 + 改进建议 |

> **两者都必须显式输出，不得沉默。** 沉默会被误读为"没问题"。

## 9. 指标实现检查表

**每实现一个指标，必须完成下列全部项：**

- [ ] 公式与本文档一致
- [ ] 线段角使用 `atan2`，并通过 §1.4 的四象限验算用例
- [ ] 关节角参数顺序正确（顶点居中）
- [ ] 事件帧指标使用原始坐标，未经平滑
- [ ] 时间类指标使用 `fps_verified`
- [ ] **视角校验已实现**：视角不匹配时返回 `view_mismatch`
- [ ] **有效测量窗校验已实现**：窗外帧已排除
- [ ] 位移类指标在无参考尺度时返回 `insufficient_data`
- [ ] 绝对速度类指标**未实现**（本项目不输出）
- [ ] `min_fps` 校验已实现
- [ ] 有效帧 < 3 时返回 `insufficient_data`
- [ ] 至少 3 个**手工验算**测试用例通过
- [ ] 输出包含 `confidence`、`reliability`、`reliable`、`reliability_note`
- [ ] 输出包含 `perspective_error_estimate`
- [ ] 若依赖标准值，`ref` 包含 `applicable_phase` 与 `source`

### 9.1 关于"手工验算"

> **测试必须是手工验算，而不是"与上次输出一致"。**
>
> 后者只能防回归，不能防一开始就错。一个从第一天就错了十倍的计算，快照测试会忠实地一直通过。
