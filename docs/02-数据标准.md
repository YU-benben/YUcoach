# 第一部分 · 拍摄标准

## 1. 拍摄方式说明

本标准针对**固定站位 + 镜头跟随运动员移动**的拍摄方式制定。

| 项 | 说明 |
|---|---|
| 拍摄者位置 | 相对跑道固定，不移动脚步 |
| 镜头 | 跟随运动员转动（水平摇摄） |
| 结果 | 运动员始终在画面内，但**位置、距离、视线方向逐帧变化** |

### 1.1 这种拍摄方式带来的三个后果

| 后果 | 影响 |
|---|---|
| 运动员偏离画面中心 | 视线偏斜，投影到画面的角度 ≠ 真实角度 |
| 距离逐帧变化 | 运动员的像素尺寸变化，无法用固定比例换算 |
| 背景逐帧移动 | 无法用背景参照物做全局尺度标定 |

### 1.2 本标准的应对总策略

| 策略 | 说明 |
|---|---|
| 定义有效测量窗 | 只采信运动员处于画面中心区域的帧 |
| 用逐帧尺度而非全局尺度 | 每帧用运动员自身肢体长度做参考 |
| 区分指标敏感度 | 角度与时间类可用，位移类降级 |
| 显式输出误差估计 | 不隐瞒，让用户知道哪些数可信 |

## 2. 三种视角

### 2.1 视角定义

| 视角 | 拍摄位置 | 可见平面 | 主要可测内容 |
|---|---|---|---|
| **侧面** `side` | 跑道侧面，与跑道垂直 | 矢状面 | 髋/膝/踝角度、躯干前倾、大腿摆动 |
| **正面** `front` | 运动员前方 | 额状面 | 骨盆倾斜与旋转、膝内外翻、着地宽度、躯干侧倾 |
| **背面** `back` | 运动员后方 | 额状面 | 同正面 + 臀中肌控制、足跟外翻 |

### 2.2 视角不可混用 ⚠️

> **用正面视频算"膝关节角"，得到的是完全不同的几何量。**

| 视角 | 能测 | **不能测** |
|---|---|---|
| 侧面 | 矢状面角度 | 骨盆旋转、膝内扣、着地宽度 |
| 正面 / 背面 | 额状面指标 | **所有矢状面角度** |

**因此视角是必须填写的采集参数，直接决定哪些指标会被计算。**

### 2.3 各视角的特殊要求

| 视角 | 要求 |
|---|---|
| **侧面** | 镜头光轴应尽量垂直于跑动平面；运动员跑动方向建议由画面左向右（便于角度正负号统一） |
| **正面** | 镜头应对准运动员来向；拍摄者不要站在运动员的跑动路线上 |
| **背面** | 镜头应对准运动员去向；注意不要被其他运动员遮挡 |

## 3. 帧率要求

短跑单脚触地时间约 80–120 ms。

| 帧率 | 单帧间隔 | 触地期内帧数 | 触地时间误差 | 判定 |
|---|---|---|---|---|
| 30 fps | 33.3 ms | 2–4 帧 | > 30% | ❌ 时间类不可用 |
| 60 fps | 16.7 ms | 5–7 帧 | 约 17% | ⚠️ 勉强 |
| **120 fps** | **8.3 ms** | **10–14 帧** | **约 8%** | ✅ **门槛** |
| 240 fps | 4.2 ms | 19–28 帧 | 约 4% | ✅ 推荐 |

### 3.1 门槛定为 120 fps

低于 120 fps 时，下列指标直接判为不可用：

- `ground_contact_time`（触地时间）
- `flight_time`（腾空时间）
- `duty_factor`（占空比）

**判定方式是返回"数据不足"，而不是给一个"大概"的数。**

### 3.2 怎么拍到高帧率

| 方式 | 说明 |
|---|---|
| 手机慢动作模式 | 主流安卓旗舰支持 1080p@240fps；设置里选"慢动作" |
| 专业相机 | 高速录制模式 |

**注意**：部分手机在慢动作模式下会**自动降帧率**（光线不足时）。拍摄后应在 App 中核对实际帧率。

## 4. 机位参数

| 参数 | 要求 | 违反后果 |
|---|---|---|
| 拍摄距离 | 8–15 m | 过近畸变大，过远关键点像素不足 |
| 相机高度 | 约等于运动员髋高（1.0–1.3 m） | 偏离过大产生俯视/仰视透视变形 |
| 画面占比 | 运动员身高占画面高度 **50–70%** | 过小则关键点精度不足 |
| 曝光 | **锁定** | 自动曝光会导致关键点随亮度漂移 |
| 对焦 | **锁定** | 跑动中失焦 |
| 快门速度 | ≥ 1/1000 s | 运动模糊致关键点位置偏移 |
| 光学防抖 | 可开 | — |
| **电子防抖** | **关闭** | 会引入帧间几何变形，破坏逐帧尺度一致性 |
| 数字变焦 | **禁用** | 损失有效像素 |

### 4.1 曝光锁定与跟踪拍摄的冲突 ⚠️

**跟踪拍摄时光线条件会变化**（运动员从阴影跑进阳光，或镜头转向不同亮度的区域）。

| 处理方式 | 后果 |
|---|---|
| 锁定曝光 | 部分帧可能过暗或过亮，但**关键点位置稳定** |
| 自动曝光 | 画面亮度均匀，但**关键点随亮度漂移** |

> **必须锁定曝光。** 关键点位置稳定性比画面美观重要得多。
>
> 若光线变化剧烈，应选择光线稳定的时段拍摄，或接受部分帧标记为低质量。

### 4.2 画面占比的权衡

| 占比 | 问题 |
|---|---|
| < 35% | 膝踝像素距离过小，角度误差成倍放大 |
| **50–70%** | **最佳区间** |
| > 80% | 跟踪拍摄时容易跟不上，运动员出画 |

## 5. 有效测量窗 ⚠️

> **这是跟踪拍摄下最重要的质量控制机制。**

### 5.1 定义

**有效测量窗 = 运动员投影中心落在画面中心区域内的帧范围。**

| 区域 | 判定 | 处理 |
|---|---|---|
| 画面中心 ±20% | **有效** | 正常参与计算 |
| ±20% – ±35% | **降级** | 关键点 `q` 降为 `1`，置信度乘 0.6 |
| > ±35% | **排除** | 该帧不参与计算 |

**画面中心区域的定义**：以画面中心为原点，宽高的 ±20% 为半径的矩形区域。

```
┌─────────────────────────────────┐
│                                 │
│        ┌───────────────┐        │
│        │               │        │
│        │  有效测量窗    │  ← 运动员在此区域内，测量可信
│        │               │        │
│        └───────────────┘        │
│                                 │
└─────────────────────────────────┘
```

### 5.2 为什么要这个机制

运动员偏离画面中心时视线偏斜，投影到画面的角度不等于真实角度：

| 视线偏斜 | 角度误差量级（对 30° 的真实角度） |
|---|---|
| 0° | 0° |
| 10° | < 1° |
| 15° | 约 1° |
| 30° | 3–4° |
| 45° | 6–8° |

**关键点**：这个误差是**系统性的**，不会因重复测量而减小。所以必须通过限制有效区域来控制，而不是靠平均。

### 5.3 有效帧不足时的处理

| 情况 | 处理 |
|---|---|
| 某指标的有效帧 < 3 | 该指标返回 `insufficient_data`，原因 `perspective_error` |
| 整体有效帧占比 < 50% | 报告顶部横幅提示"拍摄跟踪过快，部分指标精度受限" |
| 整体有效帧占比 < 25% | 报告顶部横幅提示"建议改用固定机位或减慢跟踪速度" |

### 5.4 拍摄时怎么保证有效帧够

| 建议 | 说明 |
|---|---|
| 让运动员在画面中心区完成被分析的步次 | 需要提前预判，镜头提前到位 |
| 镜头转动要平滑 | 突然的加速转动会让运动员瞬间偏移出中心区 |
| 优先分析画面中心区那几步 | 即使其他步次不可用，只要中心区有 3 个完整步次就够 |
| 必要时拍两段 | 一段专门拍起跑，一段专门拍途中跑 |

## 6. 参考尺度

> **没有参考尺度，位移类指标无法换算。**

### 6.1 跟踪拍摄下的尺度来源

| 来源 | 可用性 | 精度 |
|---|---|---|
| **运动员自身肢体长度** | ✅ 每帧都有 | 中（需知道身高） |
| 画面中的跑道分道线 | ⚠️ 仅在可见时 | 高 |
| 已知长度的标定物 | ⚠️ 需自备 | 高 |

### 6.2 逐帧尺度（推荐方案）

跟踪拍摄时距离逐帧变化，**全局尺度不成立**。因此采用**逐帧尺度**：

```
每帧的参考 = 该帧中运动员的某个已知长度
```

| 参考量 | 说明 |
|---|---|
| 大腿长（髋→膝） | 稳定性好，遮挡少 |
| 小腿长（膝→踝） | 稳定性好 |
| 躯干长（颈→髋） | 稳定性好，但正面视角遮挡多 |
| 身高（头→足） | 仅适用于直立姿态，跑动中不可用 |

**实现方式**：用同一段视频中**所有帧的该肢体长度中位数**作为该运动员的参考长度，再按人口统计学比例换算为米。

```
该帧的 pixels_per_meter = 该帧的肢体像素长度 / 该肢体的中位长度 × 全局ppm
```

**优点**：不受距离变化影响。
**缺点**：精度依赖人口统计学比例，有 5–10% 的个体误差。

### 6.3 跑道分道线（最优但受限）

标准田径跑道分道线间距 **1.22 m**。

| 条件 | 说明 |
|---|---|
| 可用条件 | 画面中同时可见 ≥2 条分道线 |
| 跟踪拍摄下的问题 | 分道线在画面中的位置逐帧变化，**每帧都需要重新识别** |
| 精度 | 高（±3%） |

**实现要求**：逐帧检测分道线位置，若某帧无法检测到 ≥2 条，该帧降级为使用逐帧尺度或标记为无法换算。

### 6.4 参考尺度的选择策略

```
若该帧可见 ≥2 条分道线  → 用分道线（高精度）
否则若已知运动员身高      → 用逐帧肢体尺度（中精度）
否则                     → 位移类指标返回 insufficient_data
```

## 7. 畸变校正

广角镜头边缘畸变可达数个百分点，会让画面边缘的角度完全失真——而跟踪拍摄时运动员恰好经常处于边缘。

### 7.1 标定规程

| 步骤 | 操作 |
|---|---|
| 1 | 用棋盘格（建议 9×6 内角点，方格 25 mm）拍摄 15–20 张 |
| 2 | 覆盖整个画面，含四角，含 ±30° 倾斜 |
| 3 | OpenCV `calibrateCamera` 求内参与畸变系数 |
| 4 | 重投影误差 **必须 < 0.5 px** |
| 5 | 参数存为该相机的标定档案，同一相机复用 |

### 7.2 复标定触发条件

- 相机跌落或受撞击 → 立即
- 变焦或改变对焦距离 → 立即
- 更换镜头 → 立即
- 距上次标定超过 6 个月 → 定期
- 更换手机 / 相机 → 重新

### 7.3 无畸变参数时的处理

| 区域 | 处理 |
|---|---|
| 画面中心 ±20% | 正常输出 |
| 该区域外 | 关键点 `q` 降至 `1`，置信度乘 0.7 |
| 报告中 | 必须注明"本次未做畸变校正" |

## 8. 帧率可信度协议 ⚠️

> **视频容器的帧率元数据不可信是一个真实存在的问题，且它出错时不会报错，只会安静地输出错误的时间指标。**
>
> 典型情形：手机慢动作视频导出后，容器帧率被写为 30 fps，而实际时间基准是 240 fps。此时触地时间会算成实际值的 8 倍。

### 8.1 三项校验方法

**任何分析开始前必须执行下列校验，至少两项一致（偏差 < 5%）方可继续。**

#### 方法 A —— 时长比对

```
校验帧率 = 总帧数 / 实测时长
```

实测时长用秒表或视频编辑软件读取，**不使用容器声称的时长**。

#### 方法 B —— 步频反推

```
校验帧率 = 相邻同侧触地间隔帧数 × 步频 / 60
```

**步频合理性区间：**

| 人群 | 步频范围 |
|---|---|
| 普通人慢跑 | 140–160 步/分 |
| 业余跑者 | 160–200 步/分 |
| 精英短跑 | 240–280 步/分 |
| 人类极限 | ~300 步/分 |

若假设的帧率算出的步频落在 120–300 之外，则该假设错误。

#### 方法 C —— 尺度位移法

用参考尺度换算出的米制位移，配合该项目的合理速度区间反推。

**男子 100 m 合理速度区间：**

| 阶段 | 速度 |
|---|---|
| 起跑后第 1 步 | 2–4 m/s |
| 加速段（10 m 处） | 5–7 m/s |
| 途中跑最大速度 | 10–12 m/s |

**注意**：跟踪拍摄下此方法精度下降，仅作辅助交叉验证。

### 8.2 判定与处理

| 情况 | 处理 |
|---|---|
| 两法一致，偏差 < 5% | **通过**，采用 `fps_verified` |
| 偏差 5–15% | **警告**，时间类指标 `confidence` 乘 0.6 |
| 偏差 > 15% 或无法一致 | **拒绝时间类指标**，仅输出角度类 |

### 8.3 App 端能做的初级校验

三法中的步频反推需要在服务端做姿态分析，因此 **App 端只能做初级校验**：

| 检查 | 能发现什么 |
|---|---|
| 声明帧率 × 时长 ≈ 帧数 | 容器元数据自相矛盾（**变速导出的典型症状**） |
| 文件可解码性 | 损坏文件 |
| 帧数是否足够 | 素材过短 |

**App 端做初级校验的意义**：让用户在**上传前**就知道素材可疑，而不是等分析完才被告知。前者只需重选文件，后者要重传几百 MB。

## 9. 素材拒收清单

### 9.1 硬拒收（不得进入分析）

| 编号 | 情况 |
|---|---|
| X1 | 无法解码 / 文件损坏 |
| X2 | 完整步次少于 3 个 |
| X3 | 运动员全程出画或被裁切 |
| X4 | 帧率校验三种方法全部失败 |
| X5 | 严重逆光致关键点不可辨 |
| X6 | 画面存在明显拖影（快门过慢） |

### 9.2 降级处理（可分析但限制指标）

| 情况 | 降级方式 |
|---|---|
| 帧率 60–119 fps | 时间类指标标记低置信，报告中说明 |
| 帧率 < 60 fps | 时间类指标返回 `insufficient_data` |
| 无参考尺度 | 位移类指标返回 `insufficient_data` |
| 未做畸变校正 | 画面边缘帧标记存疑 |
| 有效帧占比 < 50% | 报告横幅提示精度受限 |
| 视角与请求指标不匹配 | 该指标返回 `insufficient_data`，原因 `view_mismatch` |

## 10. 拍摄质量评分

每次采集自动生成 0–100 分。

| 分项 | 权重 | 扣分规则 |
|---|---|---|
| 帧率 | 25 | ≥240 满分；120–239 扣 5；60–119 扣 12；<60 扣满 |
| 参考尺度 | 20 | 分道线法满分；身高+肢体尺度扣 8；无参考扣满 |
| 视角适配度 | 15 | 光轴偏角每 1° 扣 3 |
| 画面占比 | 10 | 超出 50–70% 区间每 10% 扣 3 |
| **有效帧占比** | **15** | <90% 每降 10% 扣 3；<50% 扣满 |
| 曝光与模糊 | 10 | 目视有明显模糊扣 5–10 |
| 帧率校验一致性 | 5 | 偏差每 5% 扣 2；未校验扣满 |

### 10.1 质量分的用途

| 分数 | 报告处理 |
|---|---|
| ≥ 75 | 附录中标注方法学局限 |
| 55–74 | 报告顶部横幅："本报告部分指标精度受限" |
| < 55 | 报告顶部横幅："本报告结论仅供参考，不建议用于训练决策" |

### 10.2 质量分与可靠性的关系

质量分**不直接决定**单个指标的 `reliable` 状态。二者独立：

- 质量分是**整批数据**的综合评价
- `reliable` 是**单个指标**的方法学判断

## 11. 现场操作清单

### 11.1 准备（一次性）

- [ ] 完成相机畸变标定（重投影误差 < 0.5 px）
- [ ] 确认相机可输出 120 / 240 fps（实机录制验证）

### 11.2 每次采集前

- [ ] 确定视角（侧 / 正 / 背），记录
- [ ] 架设位置：距跑道 8–15 m，高度约髋高
- [ ] 相机设置：帧率 120/240；**曝光锁定**；**对焦锁定**；快门 ≥1/1000 s；**电子防抖关闭**；禁用数字变焦
- [ ] 取景确认：运动员占画面高度 50–70%；画面中尽量包含跑道分道线
- [ ] 试拍 3 秒回放：无模糊、无失焦

### 11.3 采集时

- [ ] 记录运动员信息（姓名、身高、体重、项目）
- [ ] 跟踪转动要平滑，避免突然加速
- [ ] 尽量让运动员处于画面中心区
- [ ] 拍摄结束后立即回放检查

### 11.4 采集后

- [ ] 记录实际拍摄距离与相机高度
- [ ] 确认视频文件完整可播放
- [ ] 若为慢动作导出，**必须记录导出设置**
- [ ] 在 App 中填写采集信息并上传

# 第二部分 · 标注标准

> 人工标注是**唯一真值基准**。自动方法达标的标准就是"接近人工标注"。

## 12. 第一原则

> ## 禁止猜测。看不见就留空。
>
> 猜测一个被遮挡的膝关节位置，等于给整批数据注入**无法检测的偏差**。
>
> 它不会报错，不会产生异常值，只会让"人工真值"整体失去可信度——而人工真值是全项目唯一的地基。

---

## 13. 关键点标注（16 点）

见 `01-术语与命名规范.md` §4 的完整定义。

### 13.1 精确位置要求

| 关键点 | 标注位置 |
|---|---|
| `head` | 头部轮廓的几何中心（不是面部特征点） |
| `neck` | 第七颈椎位置，颈根与躯干交界处 |
| `shoulder` | 肩关节旋转中心，约在肩峰下方 |
| `hip` | 髋关节旋转中心，约在大转子高度 |
| `knee` | 膝关节旋转中心，约在髌骨后方 |
| `ankle` | 踝关节旋转中心，约在外踝高度 |
| `heel` | 足跟最后端 |
| `toe` | 趾尖最前端 |
| `pelvis_center` | 左右髋连线中点 |
| `shoulder_center` | 左右肩连线中点 |

**定位原则**：标**关节旋转中心**，不标骨骼突起。位置选择错误会导致该关节角度产生恒定偏移。

### 13.2 不同视角的标注要点

| 视角 | 要点 |
|---|---|
| **侧面** | 远侧肢体常被遮挡，遮挡时留空不猜。特别注意区分左右腿 |
| **正面** | 左右腿在画面中呈镜像，**注意左右不要标反**（画面左侧是运动员右侧） |
| **背面** | 同正面，但**画面左侧是运动员左侧** |

> **正/背视角的左右判定方向相反，这是最容易出错的地方。**

## 14. 事件标注（8 类）

见 `01-术语与命名规范.md` §8 的完整定义。

### 14.1 着地判定（最关键）

> **定义：鞋底与地面发生视觉可见接触的第一帧。**
>
> **鞋底形变发生在接触之后，不作为判定依据。**

**辅助线索（按可靠性排序）：**

| 序 | 线索 | 注意 |
|---|---|---|
| 1 | 鞋底与地面之间的亮缝消失的那一帧 | **以此为准** |
| 2 | 脚踝竖直位置达到局部极小值 | ⚠️ 极小值通常在接触**之后**，不可当接触帧 |
| 3 | 脚的水平速度骤降 | 需逐帧比对 |

### 14.2 离地判定

> **定义：趾尖与地面失去接触的最后一帧。**

从下一帧起，足部整体（含趾尖）开始持续向上运动。

**跟踪拍摄的影响**：镜头移动时地面在画面中的位置会变化。判定时以**运动员足部与该帧地面的相对位置**为准，不以画面固定坐标为参考。

## 15. 标注范围与选帧

### 15.1 标注区间

| 边界 | 规则 |
|---|---|
| 起点 | `block_clearance`（或视频起始的第一个完整步次） |
| 终点 | 最后一个**完整**步次 |
| 不完整步次 | 不标 |
| 有效测量窗外的帧 | **不标**（标了也不能用） |

### 15.2 每个完整步态循环标 4 帧

| 序 | 帧类型 | 支撑的指标 |
|---|---|---|
| 1 | `touchdown` | 着地胫骨角、着地膝角 |
| 2 | `midstance` | 支撑中期膝角 |
| 3 | `toe_off` | 离地髋角 |
| 4 | `swing_peak` | 大腿摆动幅度 |

### 15.3 最小标注量

> **必须连续标注至少 3 个完整循环（每侧 12 帧，共 24 帧）。**

| 循环数 | 可计算 |
|---|---|
| 1 | 只能得到单次采样值 —— **不可用于判断** |
| 2 | 可算差值，无法估计变异 |
| **3** | **可算均值与变异，指标才具备统计意义** |

## 16. 遮挡与边界裁决

> **本表必须在标注开始前填完，填写后不得临场更改。**
>
> 临场裁决会导致同类情况在不同批次中处理不一致，使数据不可比。

| 情况 | 裁决 |
|---|---|
| 关节被身体遮挡 | 该点 `q = 0`，坐标留空，**不猜** |
| 关节被运动模糊覆盖但位置可明确推断 | 标出，`q = 1` |
| 左右腿完全重叠 | 远侧腿全部 `q = 0` |
| 足部被裁切出画 | 该帧作废，不标 |
| 运动员处于有效测量窗外 | 该帧作废，不标 |
| 前脚掌先着地 vs 后跟先着地 | 按实际位置标点，不预设立场 |
| 接触点落在跑道白线上 | 正常标 |
| 慢放后仍无法确定（±1 帧） | `ambiguous = 1`，`note` 写明原因 |

**`ambiguous = 1` 的帧在分析中统一排除。**

## 17. 质量控制协议

**四道 QC 全部通过，标注方可进入分析。**

### QC-1 组内信度（标注完成 7 天后执行）

| 步骤 | 操作 |
|---|---|
| 1 | 随机抽取 15 帧 |
| 2 | **不看原答案**重新标注 |
| 3 | 计算差异 |

| 指标 | 目标 |
|---|---|
| 事件帧号平均绝对差 | ≤ 1 帧 |
| 关键点平均像素距离 | < 5 px @ 1080p |

> **这个数字即人工基准误差，同时定义了自动方法的目标。**

### QC-2 几何一致性（自动检查，必须通过）

**原理：人体肢长是常数。**

| 部位 | 允许变异系数 |
|---|---|
| 大腿长（髋→膝） | < 3% |
| 小腿长（膝→踝） | < 3% |
| 躯干长（颈→髋） | < 3% |
| 头颈长（头→颈） | < 5% |

**离群帧定位**：偏离中位数超过 3 × MAD 的帧需回工具复查。

**附加检查**：任意两个关节标在同一位置（距离 < 5 px）视为失误。

### QC-3 生理合理性（自动检查，超限需复查）

| 检查项 | 合理区间 |
|---|---|
| 着地膝角 | 150° – 178° |
| 支撑中期膝角 | 必须小于同一步的着地膝角 |
| 离地髋角 | 150° – 182° |
| 膝角全局 | 40° – 181° |
| 骨盆倾斜（额状面） | −15° – +15° |

> 这些区间用于抓"点错了关节"这类硬错误，**不是精确判据，不构成对运动表现的结论**。

### QC-4 叠加目视（人工，逐帧确认）

将关键点叠回原始视频帧，逐张确认：

- [ ] 每个点是否落在正确的关节上
- [ ] 骨架连线形态是否合理（无扭曲、交叉、断裂）
- [ ] 头→颈→肩→髋→膝→踝→趾的上下关系正确
- [ ] **左右侧未标反**（正/背视角尤其注意）

> **这一条不能省，且不能用脚本代替。**
>
> CSV 里的数字看起来再合理，也可能整体错位。只有把点画回画面上，才能一眼看出对错。

### QC 不通过的处理

| QC | 处理 |
|---|---|
| QC-1 | 计算实际误差值并记录，作为本批次基准误差 |
| QC-2 / QC-3 | 定位可疑帧 → 回工具复查 → 修正后重跑 |
| QC-4 | 发现系统性错误 → 整批重标 |

## 18. 导出格式

### 18.1 文件命名

```
<session_id>_events.csv
<session_id>_keypoints.csv
```

`session_id` 格式：`s_<yyyymmdd>_<athlete>_<seq>`

**同一运动员的不同次拍摄必须使用不同 `seq`** —— 这是后续做重测信度分析的基础。

### 18.2 事件表

```csv
session_id,frame,event,side,step_index,ambiguous,note
s_20260301_at00007_01,142,touchdown,R,1,0,
s_20260301_at00007_01,151,midstance,R,1,0,
s_20260301_at00007_01,170,toe_off,R,1,0,
s_20260301_at00007_01,178,swing_peak,R,1,0,
```

| 列 | 必填 | 说明 |
|---|---|---|
| `session_id` | ✅ | 与关键点表一致 |
| `frame` | ✅ | 原始视频帧号 |
| `event` | ✅ | 8 类枚举之一 |
| `side` | ✅ | **不允许留空** |
| `step_index` | ✅ | 该侧第几步，从 1 开始 |
| `ambiguous` | ✅ | `0` / `1` |
| `note` | — | `ambiguous = 1` 时必填原因 |

### 18.3 关键点表

```csv
session_id,frame,head_x,head_y,head_q,neck_x,neck_y,neck_q,...,shoulder_center_q
```

| 列 | 说明 |
|---|---|
| 列数 | `2 + 16 × 3` = **50 列** |
| 坐标 | 像素，原点在画面左上角，y 轴向下 |
| `q` | 质量码 `0` / `1` / `2` |
| 缺失点 | `x`、`y` 留空，`q` 填 `0` |
| 小数位 | 2 位，**不得四舍五入到整数** |

> **导出后第一件事：核对列数 = 50。**
>
> 对不上就是漏点或列错位。列错位是灾难性的且难以察觉——所有角度都会算错，但数值看起来仍在合理范围内。

**列顺序固定**：严格按 `01-术语与命名规范.md` §4 的编号 0–15 排列，不得因某点缺失而调整。

## 19. 标注工作流程

```
准备
  ├─ 填写视频元数据（帧率、视角、机位参数、参考尺度）
  ├─ 填写裁决表
  └─ 确认左右朝向（侧面 / 正面 / 背面各不相同）
        ↓
标注
  ├─ 先标事件（事件决定需要标哪些帧）
  └─ 按事件帧标关键点
        ↓
自检
  ├─ 运行 QC-2、QC-3 自动检查
  └─ 生成叠加图，执行 QC-4 目视
        ↓
修正
  └─ 回工具修正可疑帧 → 重跑自检
        ↓
导出
  ├─ 核对列数 = 50
  └─ 提交
```

## 20. 常见错误与其代价

| 错误 | 表面现象 | 实际代价 |
|---|---|---|
| 猜测被遮挡的关节 | 数据更"完整" | 注入无法检测的偏差，真值失去可信度 |
| 正/背视角左右标反 | 数值正常 | 所有分侧统计完全颠倒 |
| `side` 留空 | 看不出问题 | 分侧统计永久无法进行 |
| 用踝最低点当触地帧 | 看起来合理 | 触地时刻系统性延后 1–3 帧 |
| 列错位 | 数值仍在合理范围 | 所有角度算错，且极难发现 |
| 标注有效测量窗外的帧 | 更完整 | 标了也不能用，白费工时 |
| 未做 QC-4 目视 | 自动检查全通过 | 系统性错位无法被发现 |
| 开着电子防抖拍摄 | 画面更稳 | 引入帧间几何变形，逐帧尺度失效 |
| 自动曝光 | 亮度均匀 | 关键点随亮度漂移 |
| 信任容器帧率 | 一切正常 | 时间类指标静默错数倍 |

### 最重要的一条

> **上述错误的共同特征是：文件看起来完全正常，自动检查可能全部通过，数值也都落在合理范围内。**
>
> 唯一能发现它们的方法是 **QC-4 叠加目视**。这也是唯一不能自动化的环节。
