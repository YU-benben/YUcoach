## 1. 铁律

> ## 任何写入标准值库的数字，必须能指向一份可查证的原始文献，且记录页码或图表号。
>
> ## 查不到就留空。
>
> ## 留空意味着该指标只输出测量值，不做偏离判断。

### 1.1 为什么这条如此严格

| 后果 | 说明 |
|---|---|
| 结论系统性错误 | 标准值错了，所有偏离判断都错，且方向一致 |
| **无法察觉** | 数值看起来完全合理，没有任何异常信号 |
| 不可追溯 | 教练问"这个标准哪来的"，回答不出 |
| 信任崩塌 | 教练发现一次错误标准，就不再相信所有数字 |

**这是全项目唯一无法通过测试发现的错误类型。**

- 指标算错 → 可以对比真值
- 契约写错 → 有 Schema 校验
- 规则写错 → 有用例验证
- **标准值编造 → 没有任何自动检测手段**

## 2. 「与顶级运动员对比」的正确做法

> 这是本项目需求中的核心诉求。但实现方式与直觉不同。

### 2.1 不做什么

| 做法 | 为什么不做 |
|---|---|
| 收集顶级运动员的比赛视频，逐帧对比 | 机位、距离、分辨率、视角全不一致，对比无意义 |
| 训练一个"跑姿评分模型" | 需要大量标注数据，且无法解释结论来源 |
| 与某一个具体运动员的某一帧对比 | 个体差异远大于技术差异 |

### 2.2 做什么

> **与「阶段化的精英运动员特征区间」对比，而不是与某一个具体的人对比。**

```
精英运动员群体
     ↓ 文献中报告的统计量
每个指标 × 每个阶段 × 每个人群 = 一个区间（mean ± sd 或 low–high）
     ↓
你的运动员的实测值落入或超出该区间
     ↓
偏离程度 → 结论
```

**为什么这样可行**：

| 理由 | 说明 |
|---|---|
| 文献中已有大量精英短跑运动员的运动学数据 | 不需要自己采集 |
| 统计量天然消除了个体差异 | 比的是"是否落在精英群体的常见范围内" |
| 阶段化消除了动作阶段的差异 | 加速段和途中跑分开比，见 §5.2 |
| 可追溯 | 每个区间都能指向具体文献 |

### 2.3 三个层次的对比基准

| 层级 | 来源 | 优先级 | 启用条件 | 界面措辞 |
|---|---|---|---|---|
| `literature` | 公开发表的精英运动员数据 | 低 | 默认（冷启动） | "超出该类运动员的常见范围（参考值 X–Y）" |
| `team` | 本队运动员历史数据 | **高** | 同队累计 ≥30 人次 | "高于本队同水平运动员均值" |
| `global` | 平台全量数据 | 中 | 平台累计 ≥500 人次 | "高于同项目运动员均值" |

**优先级规则**：

```
若 team 层有该指标该视角该阶段的值 → 用 team
否则若 global 层有                    → 用 global
否则若 literature 层有                → 用 literature
否则                                  → 不做偏离判断，只输出测量值
```

> **队内对比的说服力最强**，因为教练信任自己的数据。
>
> 这也是要尽早积累队内数据的商业理由——它是别人拿不走的资产。

## 3. 采集流程

```
1. 检索
   └─ 记录检索式、数据库、检索日期、命中数量
        ↓
2. 筛选
   └─ 记录纳入与排除标准，以及每篇被排除的原因
        ↓
3. 提取
   └─ 逐条填入标准值条目，每行必须有出处与页码
        ↓
4. 核验
   └─ 由第二人（或 7 天后的自己）回原文复核
        ↓
5. 入库
   └─ 写入 data/standards/*.yaml，递增 std_version
```

## 4. 标准值条目结构

```yaml
- metric_id: shank_angle_touchdown
  view: side
  phase: acceleration
  population:
    gender: male
    level: elite
    event: "100m"
    age_range: "18-25"

  low: null
  high: null
  mean: null
  sd: null

  source:
    authors: ""
    year: null
    title: ""
    journal: ""
    doi: ""
    locator: ""            # 页码或图表号，必填

  measurement_note: ""     # 测量口径核对结果，必填
  extraction_note: ""      # 从哪个组、什么条件提取，必填
  verified_by: ""
  verified_date: ""
  std_version: "2026Q1"
```

### 4.1 字段要求

| 字段 | 必填 | 说明 |
|---|---|---|
| `metric_id` | ✅ | 必须在 `03-指标定义.md` 的指标清单中存在 |
| **`view`** | ✅ | **新增。** 视角必须与指标匹配，防止跨视角套用 |
| `phase` | ✅ | 必须与 `ref.applicable_phase` 一致 |
| `population.gender` | ✅ | `male` / `female` / `mixed` |
| `population.level` | ✅ | `elite` / `sub_elite` / `college` / `high_school` / `amateur` |
| `population.event` | ✅ | `100m` / `200m` / `400m` |
| `low` / `high` | ⭕ | 区间。缺失则无法做区间判断 |
| `mean` / `sd` | ⭕ | 统计量。`sd` 缺失则无法做标准化偏离 |
| `source.locator` | ✅ | **页码或图表号。这是"可查证"的核心** |
| **`measurement_note`** | ✅ | **新增。** 测量口径核对结果，见 §7 |
| `extraction_note` | ✅ | 从哪个组、什么条件提取 |
| `verified_by` / `verified_date` | ✅ | 核验人与日期 |

### 4.2 `low` 与 `high` 的来源

文献通常只报告 `mean ± sd`。**不得直接把 `mean ± 2sd` 当作区间填入而不说明。**

| 文献提供 | 处理 | `extraction_note` 写法 |
|---|---|---|
| 明确给出区间 | 直接填 | "原文报告区间为 X–Y" |
| 只给 mean ± sd | 填 mean/sd，区间按 mean±2sd 填并**注明为推算** | "原文报告 mean=X, sd=Y；区间由 mean±2sd 推算" |
| 只给 mean，无 sd | 只填 mean，其余留空 | "原文仅报告均值，无离散度数据" |

**推算的区间必须明确标注为推算，不得伪装成原文数据。**

### 4.3 `view` 字段的作用 ⚠️

> **同一个指标名在不同视角下是完全不同的几何量。**

| 情况 | 处理 |
|---|---|
| 文献报告的是侧面矢状面角度 | `view: side`，只能用于侧面视角的分析 |
| 文献报告的是正面额状面角度 | `view: front`，只能用于正/背视角 |
| 文献未说明视角 | **不得入库**，除非能从测量方法推断并记录在 `measurement_note` |

**分析时的强制校验**：

```
若 ref.view ≠ session.view 且不属于同一平面 → 该 ref 不可用，退回 null
```

### 4.4 `window` 字段：测量窗口必须对齐 ⚠️

> **「某个瞬间的值」和「某段时期的均值」不可互换。**
>
> 这是最容易误用的一类错误 —— 数据来源权威、数值看起来完全正常、
> 口径也说得清，错的只是**测的是瞬间，而我们比的是均值**。

#### 为什么加这个字段

它是**第三次拒绝数据时**才总结出来的。三次拒绝的性质完全不同：

| 次数 | 来源 | 拒绝理由 | 性质 |
|---|---|---|---|
| 1 | IAAF 2017 伦敦世锦赛报告 | 数值与常识矛盾，怀疑取错了行 | 数据可能本身是错的 |
| 2 | IAAF 2017 报告 Table 16 | 只有 3 人，已有 n=8 的替代 | 重复 |
| 3 | **Walker 2021 世界室内锦标赛** | **测量窗口不对齐** | **数据很好，但不可比** |

第三次的具体情况：

```
论文  Walker et al. 2021（2018 世界室内田径锦标赛男子 60m 决赛，
      8 名世界级选手，150 Hz 高速摄影，Journal of Biomechanics）
      Trunk Angle GC1TD = 39 ± 3°（相对水平）
      —— 起跑器蹬出后【第一次】着地那一瞬间

我们  metric_trunk_lean 的 aggregate[phase]["mean"]
      = 该阶段【所有帧的均值】，acceleration 覆盖约 5–8 步
```

加速段躯干是**单调抬起**的：

```
第1步 51° → 第2步 46° → 第4步 39° → 第6步 33° → 第8步 28°
      ↑ 论文测这里                                ↑ 我们取均值 ≈ 36°
```

论文的区间（51±2×3 = 45–57°）是整段的**峰值区间**。
照此入库，正常运动员实测均值 36° 会低于下限 45°，
**每一个正常运动员都被报「躯干抬起过早」**。

#### 取值

| 值 | 含义 | 典型来源 |
|---|---|---|
| `whole_phase` | 该阶段所有帧的均值 | 报告分段均值的运动学研究 |
| `single_event` | 某一次事件发生的那一帧 | 报告「着地瞬间」「离地瞬间」的研究 |
| `event_mean` | 只取事件帧的平均（不含中间帧） | 报告「所有着地时刻的平均」的研究 |
| `whole_run` | 整段素材的平均 | 报「全程平均步频」这类 |
| `unspecified` | 原文未说明 | 允许入库，但有对齐风险 |

#### 与指标的对应关系

**标准值的 `window` 必须与指标本身的取值方式一致。**

| 指标类型 | 指标取值方式 | 需要的 `window` |
|---|---|---|
| 逐帧角度 + 分相位取均值（如 `trunk_lean`） | 阶段均值 | `whole_phase` |
| 事件瞬间角度（如 `knee_angle_touchdown`） | 事件帧的测定值 | `single_event` |
| 全局统计量（如 `step_frequency`） | 全程平均 | `whole_run` |

#### 强制校验

`backend/standards/loader.py` 会检查：

```
window 字段缺失或取值非法 → 拒绝加载，并在门禁 G4 报错
```

**未声明窗口的数值一律不予加载** —— 因为无法判断它是否可比。

> **注意：`window` 描述的是「这条数值覆盖多长时间跨度」。**
> 它和「样本量 n」是两件不同的事，不要混淆。

## 5. 阶段与视角的双重绑定

### 5.1 阶段绑定

**同一个数字在不同阶段含义相反。**

| 指标 | 加速段 | 途中跑 |
|---|---|---|
| `trunk_lean` | 45–60° 是**优秀** | 5–15° 才是正确；>20° 是**严重错误** |

**若用途中跑的标准值去判加速段数据，会对所有正常运动员报出"躯干前倾过大"**，形成系统性误报，而且报出的数字看起来很合理。

### 5.2 视角绑定

| 指标类别 | 只能配哪种视角的标准值 |
|---|---|
| 矢状面角度 | `side` |
| 额状面指标 | `front` 或 `back`（同一平面的值可共用，但需在 `measurement_note` 中说明） |
| 时间类 | 任意视角（三种视角都可用） |

### 5.3 防护措施

1. 每个标准值条目必须声明 `view` 与 `phase`
2. 契约中 `ref.applicable_phase` 与 `metric.phase` 不一致时，偏离度强制为 `null`
3. 契约中 `ref.view` 与 `session.view` 不匹配时，该 ref 不可用
4. 规则中的阶段校验必须有专门测试用例

## 6. 队内标准值的生成

```yaml
- metric_id: shank_angle_touchdown
  view: side
  phase: acceleration
  population:
    team_id: t_sportschool_a
    gender: male
    level: college
    event: "100m"
  n: 47
  low: null
  high: null
  mean: null
  sd: null
  generated_at: 2026-06-01
  method: "队内历史数据，排除 ambiguous 帧与有效测量窗外帧，取各运动员的均值再统计"
  std_version: "team_2026Q2"
```

### 6.1 要求

| 项 | 要求 |
|---|---|
| `n` | 必须记录样本量。**n < 30 时不得启用为队内标准** |
| `method` | 必须说明统计方法 |
| 排除规则 | 必须说明排除了哪些数据 |

### 6.2 必须人工确认

**队内标准值由数据自动生成，但必须经人工确认后才启用。**

理由：自动生成的标准值若直接生效，一个异常场次（如运动员受伤、设备故障）会污染整队标准。

## 7. 测量口径核对 ⚠️

> **同一指标名称在不同文献中可能有不同定义。提取前必须核对。**

| 需核对项 | 示例 |
|---|---|
| 角度定义 | 胫骨角是相对垂直轴还是相对水平面 |
| 正负号约定 | 前倾是正还是负 |
| 参考坐标系 | 相对实验室坐标还是相对身体轴 |
| 事件判定 | 触地是首次接触还是力值超阈值 |
| 归一化方式 | 是否除以身高，是否除以腿长 |
| 测量时机 | 是峰值还是特定时刻 |
| **视角** | 矢状面还是额状面 |

### 7.1 记录要求

每一条标准值都必须在 `measurement_note` 中记录口径核对结果：

```yaml
measurement_note: >
  原文胫骨角定义为「踝-膝连线与垂直轴夹角，膝在前为正」，
  与本项目定义一致。触地定义为首帧可见接触，与本项目一致。
  数据来自三维动作捕捉，非二维视频。
```

### 7.2 口径不一致时的处理

```
口径完全一致           → 直接入库
口径可通过换算统一      → 换算后入库，在 measurement_note 说明换算方式与引入误差
口径无法统一           → 不入库
```

**口径不一致的数据不得混入同一标准值条目。**

### 7.3 三维数据用于二维系统的限制

多数精英运动员数据来自三维动作捕捉。用于二维系统时需注意：

| 差异 | 影响 |
|---|---|
| 三维测的是真实关节角 | 二维测的是投影角 |
| 二维投影角在运动员偏离画面中心时偏小 | 系统性低估 |
| 三维无投影误差 | 二维有 |

**处理**：在使用三维来源的标准值时，`measurement_note` 必须说明这一点，且该指标的可靠性等级不得为 A。

## 8. 禁止事项

| 禁止 | 原因 |
|---|---|
| 填"大概"、"典型"、"一般认为" | 不是出处 |
| 从二手综述抄数字而不查原始文献 | 综述可能转述失真 |
| 跨项目套用（用中长跑值判短跑） | 力学机制不同 |
| **跨阶段套用** | 违反阶段绑定，产生系统性误报 |
| **跨视角套用** | 矢状面与额状面是完全不同的几何量 |
| 跨性别套用 | 体型与力量差异显著 |
| 跨水平套用（用精英值判中学生） | 标准本身不适用 |
| 用个人经验值 | 不可复现 |
| **补全缺失的 `sd`** | 会导致虚假的统计显著性 |
| 把 `mean ± 2sd` 当原文区间填而不注明 | 伪装成原始数据 |
| 记不清出处时凭印象填 | **本规范存在的唯一理由** |

## 9. 核验规程

### 9.1 核验方式

| 方式 | 适用 | 可信度 |
|---|---|---|
| 第二人回原文复核 | 最理想 | 高 |
| 7 天后的自己回原文复核 | 单人项目可行方案 | 中高 |
| 交叉比对 ≥2 篇独立文献 | 辅助手段 | 中 |
| 与队内数据比对 | 合理性检查 | 中 |

### 9.2 必做的合理性检查

| 检查 | 说明 |
|---|---|
| 单位一致性 | 角度是度还是弧度；时间是秒还是毫秒 |
| 生理可行性 | 膝角不应超过 181°；步频不应超过 300 步/分 |
| 交叉文献比对 | 同一指标不同文献的值应在相近量级 |
| 与队内数据比对 | 若队内数据普遍远超文献值，说明口径可能不同 |

**任何一项不通过，必须回原文核查，不得直接入库。**

### 9.3 交叉比对的记录

```yaml
# data/standards/_cross_check.yaml
- metric_id: shank_angle_touchdown
  view: side
  phase: max_velocity
  entries:
    - source: "<文献1>"
      mean: null
    - source: "<文献2>"
      mean: null
  consistency: ""
  note: ""
```

> 不同文献的测量口径可能不同。交叉比对时若数值差异大，**优先怀疑口径差异，而非文献错误**。

## 10. 版本管理

| 变更 | `std_version` 递增 |
|---|---|
| 新增指标的标准值 | MINOR |
| 更新已有数值 | MINOR |
| 修正错误数值 | **PATCH 但必须记录修正原因** |
| 更换数据层级（文献→队内） | MINOR |
| 删除条目 | MAJOR |

### 10.1 对历史数据的影响

| `std_version` 变化 | 需重算指标 | 需重新生成报告 |
|---|---|---|
| 任意变化 | ❌ | ✅ |

**理由**：标准值只影响"偏离判断"，不影响指标本身。但报告中的偏离结论会变，必须重新生成。

### 10.2 修正记录

```yaml
# data/standards/_corrections.yaml
- date: 2026-05-12
  metric_id: knee_angle_touchdown
  view: side
  phase: max_velocity
  field: mean
  old_value: 162.0
  new_value: 158.5
  reason: "原值从综述转述提取，回查原文后修正"
  corrected_by: <姓名>
```

**修正必须留痕。** 这是唯一能发现"历史标准值曾出错"的方式。

## 12. 检索方向参考

> **以下仅为检索方向的提示，不包含任何具体数值。**
>
> **具体数值必须从原文提取，不得从此处推断。**

### 12.1 研究主题方向

| 方向 | 关注内容 |
|---|---|
| 短跑起跑生物力学 | 起跑器姿势、蹬离角度、前几步特征 |
| 加速段力学 | 躯干前倾、着地位置、水平力方向 |
| 最高速度支撑力学 | 触地时间、垂直刚度、地面反作用力 |
| 短跑运动学特征 | 步频步幅、关节角度范围 |
| 精英与次精英对比 | 水平差异体现在哪些指标上 |
| **额状面分析** | 骨盆控制、膝内外翻、着地宽度 |
| 二维与三维测量对比 | 二维测量的已知误差范围 |

### 12.2 检索时对「视角」的关注 ⚠️

**绝大部分运动生物力学文献报告的是矢状面（侧面）数据。**

额状面（正面/背面）的数据明显更少。这意味着：

| 视角 | 标准值可得性 | 应对 |
|---|---|---|
| 侧面 | 较好 | 按 §3 流程正常采集 |
| 正面 / 背面 | **较差** | 可能大部分指标查不到标准值 → **留空，只输出测量值 + 队内对比** |

**这不是问题，而是现实。** 正面/背面指标的价值主要体现在：

1. **队内趋势对比**（同一个运动员的变化）
2. **左右对称性**（不需要外部标准值，自身左右对比即可）
3. **与队内均值对比**（积累 ≥30 人次后启用）

**因此正面/背面分析应当以「队内对比」和「自身对称性」为主，不以文献标准值为主。**

## 附录 · 常见错误与其代价

| 错误 | 表面现象 | 实际代价 |
|---|---|---|
| 凭印象填数值 | 报告完整 | 结论系统性错误，无法察觉 |
| 跨阶段套用 | 数值合理 | 所有正常运动员被报缺陷 |
| **跨视角套用** | 数值合理 | 矢状面/额状面混淆，结论完全错误 |
| 补全缺失的 `sd` | 可算偏离度 | 虚假的统计显著性 |
| 从综述抄数字 | 有出处 | 转述失真，无法核验 |
| 未记页码 | 有文献名 | 无法复核，等于没有出处 |
| 未核对测量口径 | 数值相近 | 混入不同定义的数据 |
| 用三维值当二维标准 | 有出处 | 系统性低估二维测量值 |
| 队内标准未人工确认 | 自动生效 | 单个异常场次污染整队标准 |
| `n < 30` 就启用队内标准 | 有数据 | 统计量不稳定，结论抖动 |
