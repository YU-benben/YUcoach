```
   ↓

   ↓
```

## 2. 帧率校验

**三法交叉，至少两项一致（偏差 < 5%）方可继续。**

### 2.1 方法 A —— 时长比对

```python
def verify_by_duration(frame_count: int, measured_duration_s: float) -> float:
    """
    measured_duration_s 必须用秒表或视频编辑软件读取，
    不使用容器声称的时长。
    """
    return frame_count / measured_duration_s
```

### 2.2 方法 B —— 步频反推

```python
CADENCE_MIN = 120.0   # 步/分，普通人下限
CADENCE_MAX = 300.0   # 步/分，人类极限

def verify_by_cadence(td_intervals_frames: list[int],
                      assumed_fps: float) -> tuple[float, bool]:
    """
    用同侧相邻着地间隔反推：真实帧率 = 间隔帧数 × 步频 / 60
    
    做法：假设多个候选帧率，选出让步频落在合理区间的那个。
    """
    mean_interval = mean(td_intervals_frames)
    cadence = 60.0 * assumed_fps / mean_interval
    ok = CADENCE_MIN <= cadence <= CADENCE_MAX
    return assumed_fps, ok
```

**候选帧率集合**：考虑到手机慢动作的常见倍率，候选集为

```
{24, 25, 30, 50, 60, 100, 120, 200, 240, 250, 300, 480}
```

取让步频落入合理区间的那个。若多个候选都合理，取最接近声明帧率的。

### 2.3 方法 C —— 尺度位移法

```python
def verify_by_scale(displacement_m: float, frames: int,
                    assumed_fps: float, event_type: str) -> bool:
    """
    用参考尺度换算的米制位移，配合合理速度区间反推。
    
    注意：跟踪拍摄下此法精度下降，仅作辅助交叉验证。
    """
    v = displacement_m / (frames / assumed_fps)
    ranges = {
        'first_step':   (2.0, 4.0),
        'acceleration': (5.0, 7.0),
        'max_velocity': (10.0, 12.0),
    }
    lo, hi = ranges[event_type]
    return lo <= v <= hi
```

### 2.4 判定

| 情况 | `fps_verify.status` | 处理 |
|---|---|---|
| ≥2 法一致，偏差 < 5% | `verified` | 全部指标正常 |
| 偏差 5–15% | `warning` | 时间类指标 `confidence` × 0.6 |
| 偏差 > 15% 或无法一致 | `rejected` | 时间类指标返回 `insufficient_data` |

**所有时间换算必须使用 `fps_verified`。**

### 2.5 相机的实际帧率属性

**必须读取视频流的实际帧率属性，而不是容器头部的声明值。** 实现上用视频流的帧率字段，缺失时降级为"未知"。

## 3. 镜头运动检测与处理 ⚠️

> **这是本项目区别于其他同类系统的核心环节。**

### 3.1 检测是否跟随

用背景特征点的整体位移判断：

```python
def detect_camera_motion(frames: np.ndarray) -> CameraMotion:
    """
    用稀疏光流（Lucas-Kanade）跟踪背景特征点。
    
    返回：
      is_tracking: 镜头是否在移动
      motion_magnitude: 累计运动量（像素）
      is_pure_pan: 是否近似纯水平摇摄
    """
    # 1. 在首帧用 Shi-Tomasi 检测角点（排除人体区域）
    # 2. 逐帧用光流跟踪
    # 3. 统计特征点的中位位移
    # 4. 若位移方向一致且幅度大 → 判定为跟随拍摄
```

| 判定 | 条件 |
|---|---|
| 固定机位 | 特征点中位位移 < 2 px / 帧 |
| 轻度跟随 | 2–15 px / 帧 |
| 明显跟随 | > 15 px / 帧 |

### 3.2 关键认识：镜头跟随对不同指标的影响完全不同

> **不要笼统地说"镜头动了所以数据不准"。要按指标分类处理。**

| 指标类别 | 镜头运动的影响 | 原因 | 处理 |
|---|---|---|---|
| **时间类** | **无影响** | 只依赖帧号 | 正常输出 |
| **角度类** | **低影响** | 角度对像素尺度不敏感；主要受透视误差影响 | 用有效测量窗控制 |
| **相对位移** | **低影响** | 分子分母同尺度 | 正常输出 |
| **绝对位移（单步）** | **中等** | 需要逐帧参考尺度 | 用分道线或逐帧肢体尺度 |
| **绝对位移（累计）** | **高** | 误差累积 | 不输出 |
| **绝对速度** | **致命** | 需对位移求导，放大噪声 | **不输出** |

### 3.3 为什么角度类基本免疫

线段的投影角度主要由该线段两端点的**相对位置**决定：

```
投影角 ≈ 真实角 × cos(端点深度差 / 平均深度)
```

跑动中肢体的深度变化相对拍摄距离极小（例如髋踝深度差 0.5 m，拍摄距离 10 m → 比值 5%），因此对角度的影响很小。

**真正影响角度的是运动员偏离画面中心导致的透视误差**，而不是镜头本身在动。

### 3.4 为什么绝对速度不能输出

要从视频测速度需要三步：

```
像素位移 → 减去镜头位移 → 乘以像素↔米比例 → 对时间求导
```

每一步的问题：

| 步骤 | 问题 |
|---|---|
| 像素位移 | 可测 |
| 减去镜头位移 | **视差问题**：背景物体在不同深度，纯摇摄时它们的位移量不同，无法用背景反推相机的平移量 |
| 乘以像素↔米比例 | 该比例随距离逐帧变化 |
| 对时间求导 | **放大噪声**：位移的微小误差在求导后变成巨大的速度误差 |

**结论：单目视频 + 跟踪拍摄下，绝对速度在原理上不可靠。**

> **本系统不输出速度曲线。** 这是诚实的能力边界，不是技术妥协。

### 3.5 地平面距离恢复（可选，进阶）

理论上，如果知道相机内参和高度，地平面上的点可以从图像坐标恢复真实距离：

```
相机高度 h，焦距 f，俯角 θ
地面点距离 D → 图像行坐标 v = v_horizon + f·tan(θ + arctan(h/D))
```

**但跟踪拍摄时相机的俯角逐帧变化**，导致同一地面点在图像中的行坐标随帧漂移。要修正必须逐帧知道相机指向——这又需要可见的分道线。

**因此这条路只在"画面中始终可见 ≥2 条分道线"时可行。** 实现时作为可选路径，不可用时降级。

### 3.6 处理策略总结

```python
def apply_camera_motion_policy(metrics: list[MetricDef],

    for m in metrics:
```

## 4. 视角校验

### 4.1 用户声明 vs 自动推断

视角是**必填参数**，但系统应做自动推断并比对，不一致时警告。

### 4.2 自动推断依据

| 依据 | 侧面 | 正面 | 背面 |
|---|---|---|---|
| **骨盆宽度投影 / 肩宽投影** | 很小（接近 0） | 大（接近真实宽度） | 大 |
| **面部关键点可见性** | 侧面可见半张脸 | 可见整张脸 | **不可见** |
| **左右关键点重合度** | 高（远近侧重叠） | 低 | 低 |
| **双膝分离程度** | 小 | 明显 | 明显 |

**正/背面的区分主要靠面部关键点**：

```python
def distinguish_front_back(kp_seq) -> str:
    """
    正面：可见鼻子、双眼
    背面：仅可见头轮廓，面部点不可见或置信度极低
    """
    face_conf = mean([kp['nose'].conf, kp['eye_l'].conf, kp['eye_r'].conf])
    return 'front' if face_conf > 0.5 else 'back'
```

**注意**：如果关键点集合不含面部点（本项目为 16 点，无鼻子/眼睛），则需从**足部朝向**或**手臂摆动**辅助判断，或直接要求用户确认。

> **推荐做法**：以用户声明为准，自动推断仅用于发现明显错误（如用户选了侧面但骨盆投影很宽）。

### 4.3 视角不匹配时的处理

| 情况 | 处理 |
|---|---|
| 用户声明与推断一致 | 正常分析 |
| 不一致但差异小 | 按用户声明分析，报告中附提示 |
| 不一致且差异明显 | **暂停分析**，请用户确认视角 |

## 5. 参考尺度标定

### 5.1 逐帧尺度（跟踪拍摄的必然选择）

**全局尺度在跟踪拍摄下不成立**，因为距离逐帧变化。

```python
def compute_frame_scale(kp: Keypoints,
                        segment: str = 'thigh',
                        baseline_px: float = None,
                        athlete_height_m: float = None) -> float | None:
    """
    逐帧像素↔米比例。
    
    原理：用运动员自身的肢体长度作为每帧的参考，
         再按人口统计学比例换算为米。
    """
    seg_px = euclidean(kp[f'{segment}_proximal'], kp[f'{segment}_distal'])
    if baseline_px is None or seg_px is None:
        return None
    # 该帧相对于基准帧的缩放系数
    scale_ratio = seg_px / baseline_px
    # 基准帧的 ppm（由身高或分道线确定）
    base_ppm = height_to_ppm(athlete_height_m, baseline_px)
    return base_ppm * scale_ratio
```

**基准帧的选择**：取该段视频中运动员处于画面中心区、且肢体无遮挡的帧。

**参考肢体的选择**：

| 肢体 | 稳定性 | 遮挡风险 |
|---|---|---|
| 大腿（髋→膝） | 高 | 中 |
| 小腿（膝→踝） | 高 | 中 |
| 躯干（颈→髋） | 高 | **正面/背面视角遮挡严重** |
| 头颈 | 中 | 低 |

**推荐**：侧面用大腿或小腿；正面/背面用小臂或躯干。

### 5.2 分道线法（高精度，但受限）

```python
def detect_lane_lines(frame: np.ndarray) -> LaneLines | None:
    """
    检测画面中的跑道分道线。
    标准间距 1.22 m。
    
    要求：同一帧中可见 ≥2 条。
    返回每条线的像素位置。
    """
```

**跟踪拍摄下的问题**：分道线在画面中的位置逐帧变化，**每帧都要重新检测**。

**逐帧策略**：

```
若该帧检测到 ≥2 条分道线 → 用分道线算 ppm
否则                       → 用逐帧肢体尺度
两者都不可用               → 标记该帧无尺度
```

### 5.3 无参考尺度时的处理

```
所有位移类指标 → insufficient_data，原因 no_reference_scale
角度类与时间类 → 正常输出
```

## 6. 姿态提取

### 6.1 关键点集合（16 点）

见 `01-术语与命名规范.md` §4。

### 6.2 模型选择

| 方案 | 关键点数 | 足部点 | 说明 |
|---|---|---|---|
| YOLOv8/v11-pose（COCO） | 17 | ❌ **无** | 需扩展 |
| YOLO-pose + Halpe26 | 26 | ✅ | 含足部与头部细节 |
| RTMPose | 26 | ✅ | 精度更好，速度略慢 |

### 6.3 关键约束：必须有足部关键点 ⚠️

标准 COCO 17 点模型**没有趾尖与足跟**。而：

| 依赖足部点的功能 | 影响 |
|---|---|
| 着地判定（touchdown） | 无法准确判定 → **所有时间类指标失效** |
| 离地判定（toe_off） | 同上 |
| 着地方式（前掌/后跟） | 无法判定 |
| 着地胫骨角 | 踝点可用，但仍需趾点辅助 |

> **结论：必须使用含足部关键点的模型（26 点格式），或自训练补足足部点。**
>
> **这是本项目对模型的第一硬性要求。**

### 6.4 从 26 点映射到本项目 16 点

| 本项目关键点 | 来源 |
|---|---|
| `head` | `head` 或 `nose` 与双耳中点 |
| `neck` | `neck` 或双肩中点 |
| `shoulder_*` | 直接对应 |
| `hip_*` | 直接对应 |
| `knee_*` `ankle_*` | 直接对应 |
| `heel_*` `toe_*` | 直接对应 |
| `pelvis_center` | 双髋中点（计算得出） |
| `shoulder_center` | 双肩中点（计算得出） |

### 6.5 检测与跟踪

| 场景 | 处理 |
|---|---|
| 画面单人 | 直接取最高置信度的人 |
| 画面多人 | 用 ByteTrack 保持 ID 一致 |
| 运动员进入/离开画面 | 允许 ID 中断，不跨段关联 |

**干扰排除**：若画面中有其他运动员、裁判或观众，需按以下顺序选择目标：

1. 与上一帧同一 ID 的人
2. 位置最接近画面中心的人
3. 置信度最高的人

## 7. 时序平滑

| 用途 | 方法 | 参数 |
|---|---|---|
| 坐标序列 | Savitzky-Golay | 窗口 = `round(fps_verified / 10)`，取奇数；阶数 2 |

**窗口改变即视为 `algo_version` 变更（MINOR 级）。**

## 8. 有效测量窗判定

```python
def compute_valid_window(kp_seq, frame_center_tolerance: float = 0.20):
    """
    逐帧计算运动员相对画面中心的位置。
    
    返回每帧的 valid 标记与偏斜角估计。
    """
    for frame in kp_seq:
        # 用髋中心与肩中心的平均作为人体中心
        body_center = (frame['hip_center'] + frame['shoulder_center']) / 2
        dx = abs(body_center.x - 0.5)      # 归一化坐标
        dy = abs(body_center.y - 0.5)
        
        offset = max(dx, dy)
        if offset <= 0.20:
            frame['window'] = 'valid'
        elif offset <= 0.35:
            frame['window'] = 'degraded'
            frame['confidence'] *= 0.6
        else:
            frame['window'] = 'excluded'
        
        frame['skew_deg'] = estimate_skew_angle(offset, frame)
    return kp_seq
```

## 9. 事件识别

### 9.1 着地（touchdown）

**主判据：足部与地面的相对位置**

```
ground_y = 该帧地面的图像行坐标
足底_y = max(toe.y, heel.y)

着地条件：
  |足底_y − ground_y| < 阈值
  且 从该帧起连续 ≥2 帧满足
  且 前一帧不满足
```

**地面行的获取**：跟踪拍摄下地面在画面中的位置逐帧变化。

| 方法 | 说明 |
|---|---|
| 分道线检测 | 若可见，用分道线的位置推算地面行 |
| 运动员足部最低点 | 用整段视频中足部的最低位置作为地面参考 |
| 用户标注 | 允许用户手动标记地面位置 |

**降级方案**：若无法确定地面行，用"足部垂直速度由负转正"作为着地的近似判据，但需在报告中标注该判据为近似。

### 9.2 离地（toe_off）

```
从该帧起，趾尖的 y 坐标连续 ≥3 帧递减（向上运动）
且 前一帧趾尖仍接近地面
```

### 9.3 支撑中期（midstance）

```
touchdown 与 toe_off 之间，膝角取得最小值的帧
```

**若膝角数据缺失**，退化用髋中心的垂直位置最低点。

### 9.4 摆动最高点（swing_peak）

```
同侧 toe_off 至下次 touchdown 之间，大腿前摆角取得最大值的帧
其中 大腿角 = segment_angle_from_axis(knee, hip)
```

### 9.5 事件的后处理

| 步骤 | 说明 |
|---|---|
| 时序约束检查 | `midstance` 必须在 `touchdown` 与 `toe_off` 之间 |
| 步次编号 | 按同侧顺序从 1 开始编号 |
| 配对检查 | 每个 `touchdown` 必须能配对到同侧的 `toe_off` |
| 异常标记 | 不满足约束的事件标记为待人工确认 |

## 12. 与标准值对比

```python
def compare_with_reference(metric, refs) -> RefComparison | None:
    # 1. 视角校验
    if refs.view != metric.view and not same_plane(refs.view, metric.view):
        return None
    
    # 2. 阶段校验
    if refs.phase != metric.phase:
        return None       # 禁止跨阶段对比
    
    # 3. 人群匹配
    if not population_matches(refs.population, metric.athlete):
        return None
    
    # 4. 按优先级选层
    ref = pick_by_priority(refs)   # team > global > literature
    
    # 5. 计算偏离
    deviation = None
    if ref.sd is not None and ref.mean is not None:
        deviation = (metric.value - ref.mean) / ref.sd
    
    return RefComparison(ref=ref, deviation=deviation)
```

> **视角或阶段不匹配时返回 `None`，而不是强行对比。**

```yaml
id: R_SIDE_ACC_TRUNK_TOO_UPRIGHT

title: 加速段躯干过早直立
explanation: >
  加速段躯干前倾角小于该阶段应有范围，说明身体过早抬起，
  会缩短水平推进的有效做功距离。

  min_samples: 3
  max_perspective_error: 3.0
```

### 13.1 `requires` 的作用

**不满足 `requires` 时，规则不得静默跳过，必须降级为 `insufficient_data` 结论。**

新增字段：`max_perspective_error` —— 当透视误差超过该值时，结论降级。

### 13.2 规则编号规范

```
R_<视角>_<阶段>_<问题>
```

| 部分 | 取值 |
|---|---|
| 视角 | `SIDE` / `FRONT` / `BACK` / `ANY` |
| 阶段 | `SET` / `STR` / `ACC` / `TRN` / `MAX` / `DEC` / `ANY` |
| 问题 | 大写下划线，描述**缺陷本身** |

### 14.1 关键帧图渲染要求

| 元素 | 说明 |
|---|---|
| 骨架叠加 | 近侧实线、远侧虚线（侧面）；左右不同色（正面/背面） |
| 关节点 | 正常实心；`q=1` 空心；`q=0` 不绘制 |
| 角度弧线 | 在对应关节处绘制，标注角度值 |
| **尺度条** | 因跟踪拍摄导致尺度逐帧变化，关键帧图**必须标注该帧的比例尺** |
| 事件标签 | 事件中文名 + 步骤序号 + 阶段 |
| 视角标签 | 标明这是哪种视角的图 |

### 14.2 尺度条的必要性 ⚠️

跟踪拍摄下，同一段视频中不同帧的运动员像素尺寸不同。如果不标注尺度，教练会误以为"这个人变大了"。

**每张关键帧图必须画一条比例尺，标注该帧的像素↔米比例。**
