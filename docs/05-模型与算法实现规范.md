# 05 · 模型与算法实现规范

更新：2026-10-16。本文描述当前实现；未来工作明确标为待完成。

## 双路径

默认人工路径：inspect_video → validate_target / validate_review → manual_metrics → 报告与归档。不调用姿态提取器，不做空间尺度、自动接触和自动阶段判断。

实验自动路径：视频 → 所选区间 → YOLO或RTMPose → AthleteLock → 姿态/事件/指标 → 严格参考匹配 → 规则 → 报告。未带 target_selection 的旧API仍兼容旧选人方式，不能作为新App的推荐入口。

## 模型与目标关联

YOLO COCO17 映射为项目16点，足跟/脚尖几何推导；RTMPose Halpe26 足部为模型预测。后者不自动保证更准确。切换参数、版本记录见 [16](16-App模型切换.md)。

目标关联起始以框重叠选唯一候选，后续使用位置、平滑位移预测、人体高度与固定上半身HSV外观参照。空检测、歧义、交叉、跳转或断帧时抛出 TargetLostError，中断且不生成报告；不自动重找人，不插值跨身份缺口。详见 [19](19-人物锁定.md)。没有ReID训练或已认证身份准确率。

## 已知自动算法问题

[scripts/audit_analysis_logic.py](../scripts/audit_analysis_logic.py) 的诊断覆盖归一化坐标各向异性、踝高度接触方向、支撑中期定义、横纵尺度混用、忽略帧间隔、无限最近帧、旧占空比分母和单目三维旋转等问题。固定侧面人工版本绕开这些问题，不代表旧自动路径已全部修复。

后续修复顺序：统一像素/标定坐标 → 明确原始帧号与时间戳 → 以人工事件作监督 → 分侧分阶段计算 → 验证尺度与误差 → 再启用空间报告。每步需真实标注对照，不以无报错或高模型置信度验收。

## 可追溯性

保留原片、选人区间、原始帧号、事件、模型配置及算法/规则/标准版本。成功自动任务保存轨迹，失败诊断保留在临时关键帧目录。当前任务映射仍是内存状态，尚无恢复队列。
