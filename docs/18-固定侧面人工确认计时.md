# 固定侧面人工确认计时 v1

更新：2026-10-16，适用 App 1.1.1+3。

本版先提供可复核的时间测量闭环。上传页默认开启「固定侧面 · 人工确认计时」，不运行姿态模型，不使用推导足部点、分道线尺度或自动跑动阶段。关闭开关仍可使用旧的实验性自动分析；旧算法审计中发现的空间计算问题不代表已在本次全部修复。

## 使用步骤

1. 电脑重新启动更新后的分析服务，手机安装 `YUcoach-target-lock.apk`（1.1.1，构建号 3）。新旧端需要一起更新；报告契约扩展到 1.2.0，新增 `whole_run` 表示所选区间未分期。
2. 固定手机，镜头垂直于跑动方向，不移动、不跟拍、不变焦。脚底与地面必须清楚，尽量采用短曝光和充足光线。至少 120 fps，推荐 240 fps，选短片段。
3. 上传未剪辑、未变速、未补帧的原片。服务端逐帧读取并检查容器时间戳恒定、连续，误差容限为单帧间隔的 2%。不支持低帧率慢放导出、缺失时间戳或变帧率视频。
4. 填写侧面且不跟拍。上传后先框选一个完整运动员，确认起止帧（两端包含），再进入逐帧确认页，通过滑条定位、±1 / ±10 帧移动和双指放大核对鞋底。预览保留视频解码后的原分辨率，以 JPEG 95 输出，帧号从 0 开始。
5. 左右按运动员自身区分。着地是鞋底首次接触地面的帧；离地是鞋底首次完全离开地面的帧。按「左着地→左离地→右着地→右离地……」记录。点击已有事件可跳回，删除后可重新标注。
6. 选连续清晰区间，至少两个完整接触，最好三个以上，以包含同脚下一次着地。首尾不完整接触不标；区间内部不能漏标。看不清边界就换素材，不要猜。
7. 核对原片时间基准、固定侧面、同一运动员及无漏标四项确认，然后计算。取消不会提交任务或扣分析额度。非法标注由服务端在扣额度之前拦截。

容器时间戳只能说明文件如何播放，不能独立证明真实拍摄速度，也不能可靠识别所有重复帧和补帧。因此原片确认是必要条件，不能仅凭显示「240 fps」就保证可信。

## 计算定义

设帧率为 f，TD 是着地帧，TO 是同脚离地帧。所有差值使用原视频帧号，不压缩时间轴、不平滑事件、不从姿态推断接触。

| 输出 | 公式 | 样本范围 |
|---|---|---|
| 接触时间 ms | `(TO − TD) × 1000 / f` | 每个同脚完整接触，最后汇总均值 |
| 腾空时间 ms | `(下一脚 TD − 当前脚 TO) × 1000 / f` | 两次相邻接触之间 |
| 步频 steps/min | `60000 / 相邻左右脚 TD 间隔的平均毫秒数` | 已标区间的相邻步间隔 |
| 占空比 | `(当前脚 TO − 当前脚 TD) / (同脚下一次 TD − 当前脚 TD)` | 具有下一次同侧着地的周期；不足则不输出 |

占空比以同脚完整周期为分母，不能拿一步时间作分母。例如 240 fps：左脚 TD=0、TO=24，右脚 TD=48、TO=72，左脚 TD=96、TO=120，结果为接触 100 ms、腾空 100 ms、步频 300 步/分、占空比 0.25。

报告给出样本数、均值和适用的离散统计。步频均值采用总步数/总时间，最小最大值来自单步瞬时步频，不报告与该汇总定义不一致的标准差。只有一周期的占空比不代表稳定水平。

单帧时间分辨率：120 fps 为 8.333 ms，240 fps 为 4.167 ms。若两端各误差 ±1 帧，时长最坏误差分别是 ±16.667 / ±8.333 ms。这是假设边界误差下的条件界限，不是已测得精度；模糊、漏标、误认人物、左右脚弄反仍可造成更大误差。

## 报告边界

- 不输出步长、速度、身体角度和三维旋转等空间测量值，不套用未经物理验证的尺度。
- 不自动识别加速或途中跑阶段，所有指标写为所选区间未分期；不自动触发标准值偏差或训练建议。
- 报告标明 `manual-contact 1.0.0`，不会把人工结果标成某个姿态模型的测量结果。
- 报告显示前 12 个原始事件画面，完整事件保存在电脑标注文件中。质量分仍是现有整份报告的覆盖评分，包含缺失尺度和姿态的扣分，不能当作人工计时精度或测量误差。
- 标注基于人工核对同一运动员；人工路径不运行自动身份跟踪或接触候选。实验自动模式另有保守人物关联，见 [19](19-人物锁定.md)；多人画面仍需逐帧复核。

## 电脑存储

成功任务保存到 `D:\YUcoach\data\manual_timing\<job_id>\`：

- `video.mp4` / `video.mov` / `video.avi` 等：收到的原始视频副本。
- `review.json`：视频和任务 ID、运动员 ID/姓名、四项确认、全部左右脚事件、target_selection 和保存时间。
- `report.json`：本次报告、指标及算法版本。

此目录不受上传缓存的 24 小时清理影响，已排除在 Git 跟踪之外，需要自行备份和管理容量。原始预览、临时上传和报告关键帧仍遵循现有缓存机制。当前任务列表仍在内存中，重启后不能自动从 App 恢复历史任务，但电脑的上述文件会保留。

数据可用于接触检测训练/评估和人工复核，但应先二次审核。人工勾选不等于经过验证的真值；后续训练集/验证集/测试集应按运动员和拍摄场次分开，避免同一视频的相邻帧泄漏。未经评估不会自动训练、替换模型或修改标准库。

## 验证范围

已用可控帧号验证上述数值、同侧分母、非法标注拦截和帧号从零计数；用真实编码的合成视频验证解码、接口、报告契约及存档；用 Flutter 交互测试验证左右脚标记和四项确认。此验证证明程序计算和流程，不代表已完成真实短跑视频或测力台对照实验。
